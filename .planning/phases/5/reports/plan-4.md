Open items:
- `inject::state::MAX_SUPPRESSED` caps the suppression list at 100 entries, oldest dropped, while `injected` and `brief` are uncapped. The asymmetry is deliberate (the capped list is a record to read, the other two are decided on) but it means a very long session's state file forgets the earliest refusals it reported. Nothing in phase 5 reads them back; FEED-01 owns the durable record.
- On the ordinary path no dropped set is derived, so a turn that fell out of context earlier in a session is still refused as `visible_in_session` by any prompt after the one that spent the flag. Deriving it every prompt is a query per prompt for a fact almost every prompt has no use for; INJ-05 is scoped to the one prompt after a compaction.
- `crates/verbatim/src/cmd/hook.rs`'s `inject` doc says abandoning the injection thread "is safe because nothing on that thread writes, creates a directory or takes the ingest lock (INJ-06)". As of task 2 the thread does write the per-session scratch file, which D-06 authorizes and the store still never sees.
