# Phase 5: Install from GitHub Releases - Context

Gathered: 2026-10-13
Feeds: /cad-plan 5

## Scope boundary

In: `install.sh` takes no argument or one `https://` source. With none it downloads from `https://github.com/crenshawdev/terminus/releases/latest/download`, and the two downloads become the flat names `terminus-<os>-<arch>.manifest` and `terminus-<os>-<arch>`. The script body moves into one function called on the last line, so a cut-off pipe runs nothing. The Phase 4 tests move to the flat names, new tests cover the piped forms, the default URLs and the two download refusals, and the install.sh tests also run under dash. `CHANGELOG.md` Unreleased and `DESIGN-BRIEF.md`'s install section are brought in line.
Out: publishing a release, release CI, signing and the signature check, the README (phase 6), changing Baley's `install.sh`, changing the workspace version from 0.1.1, and qualifying on macOS.
Deferred: None.
Plan shape: one plan.

## Durable decisions

- D-01 (Release asset names): A release carries two flat files per platform, `terminus-<os>-<arch>` and `terminus-<os>-<arch>.manifest`, with `<os>` `linux` or `macos` and `<arch>` `x86_64` or `aarch64`. The manifest keeps Phase 4's exact two lines, `version X.Y.Z` and `sha256 <64 lowercase hex>`. The default source is `https://github.com/crenshawdev/terminus/releases/latest/download`, written into `install.sh`. These names are the contract the future release must publish, because a GitHub release holds no folders; Phase 4's `<source>/<os>-<arch>/manifest` folder layout is replaced. Evidence: `.planning/REQUIREMENTS.md` (INST-13), `.planning/ROADMAP.md` (Phase 5), `install.sh:162-165`, Phase 4 D-06.

## Decisions

- D-02 (Arguments): With no argument the script uses the default source. With exactly one argument, it must start with `https://`, has its trailing slashes stripped as today, and replaces the default. Two or more arguments are refused. The count is checked before `$1` is read, because `set -eu` aborts on an unset `$1`. There is no environment-variable override. Evidence: `install.sh:108-110`, `.planning/REQUIREMENTS.md` (INST-13).
- D-03 (Usage line): The usage text shows the source as optional; today's `usage: sh install.sh https://<source>` names a required argument that no longer exists. The script uses no `$0`, so piping changes no other message. Evidence: `install.sh:108`.
- D-04 (Cut-off pipe): The script body moves into one function, called with `"$@"` on the last line. Flat, a download cut off at a line break runs the part that arrived: cut after the link moves, the new version is linked, `"$stable" install` never runs, and `sh` exits 0 with no receipt. The owner chose this over the roadmap's "only the argument handling and the two downloads change" and over Baley's flat body, because `curl | sh` is now the default form. Evidence: `install.sh:108-232`, `.planning/ROADMAP.md` (Phase 5 goal).
- D-05 (Stdin): Nothing in the run reads stdin. `terminus install` never reads it and starts `claude` with stdin at null, and every `read` and `digest` in the script is redirected from a file or a pipe, so the piped form needs no stdin handling. Evidence: `crates/terminus/src/cmd/install/mod.rs:18`, `crates/terminus/src/cmd/install/claude.rs:6,90`, `install.sh:72,174,187-188,200`.
- D-06 (Downloads): Only the two URLs change, to `$source/terminus-$os-$arch.manifest` and `$source/terminus-$os-$arch`. The `os`/`arch` mapping, the scratch file names `$scratch/manifest` and `$scratch/terminus`, the manifest parsing, `verify_download`, staging, the link and the final `"$stable" install` stay as Phase 4 built them. The curl flags stay `-q --proto '=https' --tlsv1.2 -fsSL`; `-L` follows GitHub's 302 from `releases/latest/download/<asset>`, measured 2026-10-13 against a real release (jq's `jq-linux-amd64`, 200 after two https redirects). Evidence: `install.sh:72,102-103,140-149,162-232`, Phase 4 D-01, D-03, D-04, D-06.
- D-07 (Before the first release): Until a release exists and `main` carries `install.sh`, the one-line install fails with `manifest download failed: <default>/terminus-<os>-<arch>.manifest`. Measured 2026-10-13: the default manifest URL and `https://raw.githubusercontent.com/crenshawdev/terminus/main/install.sh` both answer 404, and `origin/main` has no `install.sh`. This phase accepts that, and the docs keep saying no release is published yet. Evidence: `install.sh:162-163`, `CHANGELOG.md:21-22`, `DESIGN-BRIEF.md:381`.
- D-08 (Phase 4 tests): The Phase 4 tests keep running `install.sh` against the `openssl s_server -WWW` fixture, and only the served layout changes: `served/terminus-<platform>` and `served/terminus-<platform>.manifest` replace `served/<platform>/terminus` and `served/<platform>/manifest`. That touches `fixture`, `serve`, `serve_manifest`, and the two tests that build `served.join(platform()).join("terminus")` inline. Evidence: `crates/terminus/tests/install_script.rs:188-201,333-344,586,605`, Phase 4 D-10.
- D-09 (New tests): New tests cover the script fed on `sh`'s stdin with no argument, the script fed on stdin as `sh -s -- <server url>`, and two arguments refused through the existing `assert_refused` snapshot. `an_http_source_is_refused` already covers a non-https argument. Evidence: `crates/terminus/tests/install_script.rs:347-367,441-449,631-637`.
- D-10 (Fake curl): The no-argument run is proven with a fake `curl` in the test's tools folder, following the fake-`uname` pattern. It logs each URL it is asked for, writes the matching local file to its `-o` path, and lets the install finish; the test asserts the two default URLs. Tests that pass an `https://` source stay on real curl and s_server. The owner chose this over a CONNECT proxy with a throwaway `github.com` certificate and over running a copy of the script with the URL swapped. Evidence: `crates/terminus/tests/install_script.rs:14-18,291-305,405-424`.
- D-11 (Download refusals): Both `manifest download failed` and `binary download failed` are tested, by the fake curl exiting 22 for one file. s_server answers a missing file with `200 ok`, which is why Phase 4 left them untested, and a 404 on the default is what the one-line install hits today. Evidence: `install.sh:162-165`, `crates/terminus/tests/install_script.rs:20-21`, `.planning/phases/4/SUMMARY.md`.
- D-12 (dash): The install.sh tests also run under dash, because `curl | sh` runs under dash on Debian and Ubuntu, and `/bin/sh` here is bash. The owner installs dash with `sudo pacman -S dash`; it was absent on 2026-10-13. Evidence: Phase 4 D-10, `install.sh:1,6`.
- D-13 (Docs): Nothing is released, so the `CHANGELOG.md` Unreleased `Added` entry is rewritten in place to show the curl line, the optional `https://` source passed with `sh -s --`, and the flat names, with no new `Changed` line. `DESIGN-BRIEF.md:381` (the run form), `:383` ("Secondary: GitHub releases", now the default source) and `:395` ("downloads the manifest and the binary") change to match. Evidence: `CHANGELOG.md:10-27`, `DESIGN-BRIEF.md:381,383,395`.
- D-14 (Baley): Terminus's `install.sh` now departs from Baley's on argument handling, the download names and the function wrapper. Baley's script is not changed in this phase. Evidence: `/code/baley/install.sh:92-94,142-145`, Phase 4 D-06.

## Acceptance criteria

- [ ] AC1: Run with no argument, both as `sh install.sh` and with the script piped into `sh`, `install.sh` requests exactly `https://github.com/crenshawdev/terminus/releases/latest/download/terminus-<os>-<arch>.manifest` and `https://github.com/crenshawdev/terminus/releases/latest/download/terminus-<os>-<arch>`, and the install finishes.
- [ ] AC2: The script piped into `sh -s -- https://<server>` installs from that server's flat names. An `http://` argument and a two-argument run are each refused with a non-zero exit, and the stable path and the versions folder are unchanged.
- [ ] AC3: When the manifest download fails, `install.sh` exits non-zero with `manifest download failed: <url>`; when the binary download fails, it exits non-zero with `binary download failed: <url>`. In both cases the stable path and the versions folder are unchanged.
- [ ] AC4: A copy of `install.sh` cut off at any line break before its last line, piped into `sh`, changes nothing under HOME.
- [ ] AC5: A SHA-256 mismatch is still refused before anything is placed. The Phase 4 install.sh tests pass against the flat names under both `/bin/sh` and dash. `sh -n install.sh` and `dash -n install.sh` pass, and `cargo test --workspace --all-features` passes. (human-verify: needs dash)
- [ ] AC6: The `CHANGELOG.md` Unreleased entry and the `DESIGN-BRIEF.md` install section show the curl line, the optional `https://` source and the flat names, no longer mention `<source>/<os>-<arch>/manifest`, and still say no release is published yet.

## Flagged assumptions

- dash was not installed on 2026-10-13. How a test reports a missing dash is the planner's call, but a missing dash must not read as a pass. - Confident; if wrong: AC5's dash half passes without dash ever running.
- How dash handles the byte-range `case` patterns in `valid_utf8` and reading a script from a pipe is unknown until it runs. - Unclear; if wrong: the script needs a dash-safe rewrite of `valid_utf8`, inside this phase.
- A copy cut off exactly before the last line defines the function and exits 0 having done nothing. AC4 asserts no change under HOME, not the exit status. - Confident; if wrong: nothing changes for this phase.
- GitHub's `releases/latest` resolves to the most recent release that is neither a draft nor a pre-release. This comes from GitHub's documentation and was not measured here. - Likely; if wrong, or if 0.0.x builds are published as pre-releases: the default source never reaches them, which matters when the first release is published, not in this phase.
- macOS stays unqualified, as Phase 4 left it: BSD `grep -q -F` on the marker, `current_exe()` through a link, BSD `mktemp`/`readlink`/`mv -f`, and an unsigned download on aarch64. - Unclear; if wrong: the one-line install fails on a Mac.
