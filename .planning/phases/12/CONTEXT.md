- D-01 (reindex output, #41): `terminus reindex --json` gains an integer `preserved` field, named after `Rebuilt::preserved`. Evidence: `crates/terminus-core/src/reindex.rs:60-85`, `crates/terminus/src/cmd/reindex.rs:40-97`, `crates/terminus/tests/cli.rs:930-953`, `crates/terminus/tests/cli.rs:1102-1137`, `docs/json-shapes.md:186-198`.

## Decisions

- D-02 (MCP, #30): `2025-03-26` is removed from `PROTOCOL_VERSIONS`. A client that asks for it is answered `2025-06-18` (`DEFAULT_PROTOCOL_VERSION`), the path the 2026-07-28 task used. The spec settles this: a server that does not support the requested version must answer another it supports, and should answer its latest. Batching was added in `2025-03-26` and is not in `2024-11-05`, so no offered revision requires batches after this. A batch still gets the single `-32600` with a null id, and the batching comment at `rpc.rs:98-100` is corrected. A test asserts `2025-03-26` is not offered, because the existing loop over `PROTOCOL_VERSIONS` stops covering it. Evidence: `crates/terminus/src/cmd/mcp/mod.rs:58-84`, `crates/terminus/src/cmd/mcp/mod.rs:184-199`, `crates/terminus/src/cmd/mcp/mod.rs:221-259`, `crates/terminus/src/cmd/mcp/rpc.rs:94-102`, https://modelcontextprotocol.io/specification/2025-03-26/changelog, https://modelcontextprotocol.io/specification/2025-06-18/basic/lifecycle.
- D-03 (MCP, #28): A request id is accepted only when serde_json classifies it as `is_i64()` or `is_u64()`. Every number parsed as f64 is refused with `-32600`, including `1.5`, `1.0`, `1e3`, `-0` and integers outside the i64 and u64 range. The refusal carries a null id, as the object-id case does. Evidence: `crates/terminus/src/cmd/mcp/rpc.rs:105-117`, `crates/terminus/src/cmd/mcp/rpc.rs:147-155`, `crates/terminus/src/cmd/mcp/rpc.rs:198-202`, serde_json 1.0.151 without `arbitrary_precision`, https://modelcontextprotocol.io/specification/2025-06-18/basic ("Requests MUST include a string or integer ID").
- D-04 (MCP, #29): `run_get` removes duplicate ids, keeping the first occurrence of each in order, before it applies `MAX_IDS`. `served` and the "only the first N of M ids were read" reason count distinct ids. `get::records` keeps its own deduplication. Evidence: `crates/terminus/src/cmd/mcp/tools.rs:56-64`, `crates/terminus/src/cmd/mcp/tools.rs:512-531`, `crates/terminus/src/cmd/mcp/tools.rs:577-584`, `crates/terminus-core/src/recall/get.rs:80-83`, `crates/terminus-core/src/recall/get.rs:104-127`.
- D-05 (indexing, #20): `Projector::push` charges each `'\n'` to `remaining` and writes a separator only when at least one character of the next piece fits after it, so a body never ends on a bare newline. Once a piece is cut short, nothing more is appended. `DERIVED_SCHEMA` is not bumped; rows already over the cap by separator bytes stay until the next `terminus reindex`. Evidence: `crates/terminus-core/src/index/text.rs:39-46`, `crates/terminus-core/src/index/text.rs:93-103`, `crates/terminus-core/src/store/open.rs:50`.
- D-06 (indexing, #17): A boundary row needs the record's type to be `system` as well as subtype `compact_boundary`. `TurnRow::is_compact_boundary` checks the `Turn` it already carries, and `Record::is_compact_boundary`, which only tests call, gets the same rule so the two agree. `DERIVED_SCHEMA` is not bumped. #17 stays open for its second case (Deferred). Evidence: `crates/terminus-core/src/derive.rs:44-60`, `crates/terminus-core/src/derive.rs:159-165`, `crates/terminus-core/src/parse/record.rs:103-113`, `crates/terminus-core/src/parse/record.rs:159-177`.
- D-07 (indexing, #39): The miss-labelling query's `recall_get` arm is deleted. `recall_search` is matched in SQL by the extractor's rule: exact and case-sensitive, either the bare name or a name ending in `_recall_search`. The change reaches both `miss()` and replay's `sought()` through `sought_sql`. rusqlite's `functions` feature is not turned on. Existing labels are not rewritten. Evidence: `crates/terminus-core/src/feedback/label.rs:198-270`, `crates/terminus-core/src/index/entity.rs:50-67`, `crates/terminus-core/src/index/entity.rs:181`, `Cargo.toml` (rusqlite features `["bundled"]`).
- D-08 (store open, #33): `initialize` opens its transaction as IMMEDIATE (`Transaction::new_unchecked(conn, TransactionBehavior::Immediate)`), as `bring_forward` does. Nothing is re-read under the lock, because its statements are already idempotent. The regression test must fail when `initialize` is switched back to a deferred transaction and pass with the fix; how it is made deterministic is the planner's call. Evidence: `crates/terminus-core/src/store/open.rs:154-196`, `crates/terminus-core/src/store/open.rs:282-307`, `crates/terminus-core/src/store/open.rs:494-521`, `crates/terminus-core/tests/store_open.rs:901-950`, issue #33.
- D-09 (ingest, #14): `record_run` writes `files_committed = 1` and `files_failed = 0` beside its `files_seen = 1`. A single-file ingest that fails still writes no `runs` row. Rows already written with 0 are not backfilled. Evidence: `crates/terminus-core/src/ingest/mod.rs:132-148`, `crates/terminus-core/src/ingest/mod.rs:545-552`, `crates/terminus-core/src/ingest/mod.rs:1249-1276`, `crates/terminus/src/cmd/status.rs:130-137`, issue #14.
- D-10 (reindex output, #41): Without `--json`, the preserved count prints on stderr only when it is above 0, so a store with no evicted sessions prints what it prints today. `sessions` keeps meaning the sessions that were rebuilt. Evidence: `crates/terminus/src/cmd/reindex.rs:40-97`.
- D-11 (verify, #42): An evicted session that still has any block row is one session-level failure (`block: null`) that says how many rows remain. It uses the existing `Failure` shape, so `verify --json` and `docs/json-shapes.md` need no new field. The module comment that says an evicted session is never a failure is corrected. Evidence: `crates/terminus-core/src/verify.rs:27-33`, `crates/terminus-core/src/verify.rs:50-59`, `crates/terminus-core/src/verify.rs:124-178`, `crates/terminus-core/src/retention/apply.rs:125-142`.
- D-12 (cleanup, #35): `brief.rs` deletes its private `chars` and `clip` and calls the shared ones in `inject/mod.rs`. Evidence: `crates/terminus-core/src/inject/brief.rs:373-394`, `crates/terminus-core/src/inject/mod.rs:191-212`.
- D-13 (tests, #10): Only `the_lock_is_released_by_process_death` is renamed, and its comment points to `killing_ingest_anywhere_leaves_a_store_that_converges` in `crash.rs`. `a_pass_that_dies_mid_walk_still_leaves_its_runs_row` keeps its name. Evidence: `crates/terminus/tests/lock_race.rs:107-133`, `crates/terminus/tests/crash.rs:520-575`, `crates/terminus-core/tests/pass.rs:501-530`.
- D-14 (docs, #25): A field is marked nullable when its Rust type can emit null, in the bullet style the `search` section uses. In `sessions`: `project`, `project_pre_worktree`, `branch`, `first_turn_at`, `last_turn_at`, `watermark`. In `show`: `tool_name`, `ts`, `project`, `body`, `context`, and inside `context` `turns[].tool_name`, `turns[].ts`, `continues_from`, `reason`. Evidence: `docs/json-shapes.md:84-150`, `crates/terminus/src/cmd/sessions.rs:136-142`, `crates/terminus/src/cmd/sessions.rs:184-198`, `crates/terminus/src/cmd/show.rs:182-238`, `crates/terminus-core/src/recall/get.rs:36-66`, `crates/terminus-core/src/recall/context.rs:37-64`.

- `2024-10-07`, if it is still offered, is assumed to have no batching; the spec's changelog compares `2025-03-26` only with `2024-11-05` - Likely; if wrong: one offered revision still expects batches the server does not answer.
- Refusing fractional ids is assumed correct under every offered revision; only the `2025-06-18` text was checked, and JSON-RPC 2.0 says numbers SHOULD NOT have fractional parts - Likely; if wrong: an old-revision client that sends fractional ids gets refused where it was answered before.
