# Phase 3: Install Asks Nothing - Context

Gathered: 2026-10-13
Feeds: /cad-plan 3

## Scope boundary

In: `terminus install` asks nothing. The diff-and-confirm step, `--yes` and the `cleanupPeriodDays` offer go, and install ends with a receipt. Terminus stops writing `~/.claude.json`: install places the MCP entry with `claude mcp add-json --scope user`, runs no `claude` command when the entry is already correct, and reports the install incomplete with the exact command when `claude` is missing or fails. Uninstall removes the entry with `claude mcp remove --scope user` and keeps its `--purge` question. The docs that describe the old install are brought in line.
Out: `install.sh` and versioned folders behind the stable path (phase 4), where install copies the binary from (`std::env::current_exe()` stays, per phase 2 D-08), the README (phase 5), MCP entries at the project and local levels, doctor's Claude Code version floor, and uninstall's own `--yes` for `--purge`, which is unchanged.
Deferred: None.
Plan shape: multiple plans, same phase. Suggested order: the install rework with the `claude` runner and the test fake, then uninstall and doctor, then the docs.

## Durable decisions

- D-01 (Checking the entry): Install decides whether the MCP entry is already correct by reading `.mcpServers.terminus` in `~/.claude.json`, with the test doctor already uses: `type` is `"stdio"`, `command` is the stable path, `args` is `["mcp"]`, and any other key is ignored. It never runs `claude mcp get`. INST-11 forbids writes to that file, not reads. `claude mcp get` health-checks the server by spawning `terminus mcp`, prints display text with no JSON flag, exits 0 even when the health check fails, and wrote a new `userID` key into the config when measured, so using it would run `claude` on every rerun and fail criterion 2. Evidence: `crates/terminus/src/cmd/doctor.rs:481-572`, `crates/terminus/src/cmd/install/targets.rs:84-89`, `/code/baley/crates/baley/src/install/registration.rs:66-115` (Baley reads the file and returns `Unchanged`), Claude Code 2.1.296 measured 2026-10-13 in a scratch `CLAUDE_CONFIG_DIR`.
- D-02 (Ownership): Any user-level entry under the `terminus` key is Terminus's to replace, as today and as v0.1.0 phase 4 D-13 had it. Keys the user added beside the owned three, such as `env`, are carried into the JSON passed to `add-json`. This differs from Baley, which refuses an entry it cannot prove it wrote. Evidence: `crates/terminus/src/cmd/install/targets.rs:194-200,398-423`, `crates/terminus/src/cmd/uninstall.rs` (`strip_server`), `add-json` kept an `"env"` block when measured 2026-10-13.
- D-03 (Running `claude`): Install and uninstall find `claude` by scanning `PATH` themselves, as doctor's `on_path` does, and run it by absolute path with no shell, stdin at null and a deadline, the pattern of doctor's `version_of`. This reverses v0.1.0 phase 4 D-06. Its "no shell and no subprocess" contract exists only in the `targets.rs` module comment; no test or document enforces "no subprocess", the code already runs `git`, `claude --version` and itself, and the rule that is stated is "no shell". Evidence: `crates/terminus/src/cmd/install/targets.rs:62-65`, `crates/terminus/src/cmd/doctor.rs:1160-1215`, `crates/terminus-core/src/project.rs:202`, `crates/terminus/src/cmd/spawn.rs:121`, `crates/terminus-core/tests/no_network.rs`, `.planning/PROJECT.md:119`, `DESIGN-BRIEF.md:464`.
- D-04 (No network through `claude`): Every `claude` process Terminus starts gets `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, so wiring Terminus up opens no network connection and PRIV-05's and DOC-01's "no network use at all" stays true. Traced with `strace -f -e trace=connect` on 2026-10-13, one run each: `claude mcp add-json` and `claude mcp remove` both connected to `api.anthropic.com:443`; with the variable set `add-json` made no connection; with `DISABLE_TELEMETRY=1` alone it made 5. Evidence: `.planning/REQUIREMENTS.md` (PRIV-05, DOC-01), `DESIGN-BRIEF.md:315,321`, owner's ruling at context.
- D-05 (Incomplete install): When `claude` is not on `PATH`, times out or exits non-zero, install still places the binary, merges the hooks and starts the backfill. The receipt says the install is incomplete, gives the first line of stderr as the cause and the exact command to run, single-quoted with `'\''` escaping, and install exits non-zero through `Failure::Silent`, as uninstall's `finish` does. A `~/.claude.json` that cannot be parsed makes only the registration incomplete; today it aborts the whole install before anything is written. A script or phase 4's `install.sh` reads the exit status, so an incomplete install must never exit 0. Evidence: `crates/terminus/src/cmd/uninstall.rs:120-128`, `crates/terminus/src/cmd/install/mod.rs:144-147,257-262,483`, `/code/baley/crates/baley/src/install/receipt.rs:115-121,132-136`, `/code/baley/crates/baley/src/install/registration.rs:224-236`.

## Decisions

- D-06 (Placing the entry): The add is `claude mcp add-json --scope user terminus '<compact JSON>'`. An existing user-level entry in the wrong shape is fixed with `claude mcp remove --scope user terminus` and then the add, because `add-json` exits 1 with "already exists in user config" on a name that exists and leaves the file unchanged. Evidence: Claude Code 2.1.296 measured 2026-10-13, `crates/terminus/src/cmd/install/targets.rs:56-60,183-201`, `/code/baley/crates/baley/src/install/registration.rs:24-33`.
- D-07 (Deadline): Each `claude mcp` command gets a deadline longer than doctor's 2-second `VERSION_BUDGET`. `add-json` took 197-211 ms and `remove` 208-252 ms over three runs each; Baley allows 30 s. Evidence: `crates/terminus/src/cmd/doctor.rs:60`, `/code/baley/crates/baley/src/install/registration.rs:20`.
- D-08 (Removed from install): `confirm`'s call, `offer`, `Options.yes` and the `Short('y') | Long("yes")` parse arm go, so `--yes` reaches `crate::unexpected` and exits 2 as misuse, as `--json` does today. The `advise` branch that can write `cleanupPeriodDays = 3650` is deleted. Install stays without `--json` (D-24). Evidence: `crates/terminus/src/cmd/install/mod.rs:123-135,173-176,316-363,454-463`, `crates/terminus/tests/install.rs:995-1003`.
- D-09 (Confirm helper): `confirm` stays as a shared helper for `uninstall --purge` and `data move`. The install-only refusal text in `unanswerable` ("rerun with --yes") loses its only reader and goes. Evidence: `crates/terminus/src/cmd/uninstall.rs:459-473`, `crates/terminus/src/cmd/data.rs:225-247`, `crates/terminus/src/cmd/install/mod.rs:415-470`.
- D-10 (Backfill in the receipt): The backfill estimate and where to watch it are what `start_backfill` already prints: `backfill::estimate` with `print_estimate`, and `terminus status`, which reads the `runs` row. No log file is added. Evidence: `crates/terminus/src/cmd/install/mod.rs:252-306`, `crates/terminus/src/cmd/backfill.rs:109-135,165-192`.
- D-11 (`cleanupPeriodDays` in the receipt): The receipt always prints the current `cleanupPeriodDays`, the fact that transcripts older than it are already gone, and doctor's raise line, `set "cleanupPeriodDays": 3650 in <path>`, at every value, as criterion 5 reads. The value comes from the user `settings.json` only, as install reads it today. Evidence: `crates/terminus/src/cmd/install/mod.rs:53-64,316-341`, `crates/terminus/src/cmd/doctor.rs:937-978`.
- D-12 (Reformatted settings): A `settings.json` not formatted the way `JSON.stringify(value, null, 2)` writes it is still rewritten in full, now without asking. The one-time backup protects it and the receipt names the reformat as a change. The owner's file is already in that format. Evidence: `crates/terminus/src/cmd/install/json_file.rs:50-70`, `crates/terminus/tests/install.rs:944-993`.
- D-13 (Uninstall registration): Uninstall runs `claude mcp remove --scope user terminus` only when a read of `~/.claude.json` shows a user-level `terminus` entry. Without `--scope user` the remove exits 1 when a local entry also exists; with nothing there it exits 1 with "No MCP server named". If `claude` is missing or fails, uninstall prints the exact command, finishes its other steps and exits through `Failure::Silent`. Its `--purge` question and `--yes` are unchanged. Evidence: `crates/terminus/src/cmd/uninstall.rs:37-44,90-118,394-473`, Claude Code 2.1.296 measured 2026-10-13.
- D-14 (Uninstall stops writing `~/.claude.json`): `Part::McpServer`, `strip_server` and the byte restore from `.claude.json.terminus-backup` through `Document::overwrite` go. The `settings.json` strip-and-restore stays as INST-07 has it. Evidence: `crates/terminus/src/cmd/uninstall.rs:101-103,130-155,210-260,322-337`.
- D-15 (Old backups): Existing `.claude.json.terminus-backup` files are never restored and are left in place, and uninstall prints the path. The owner's is 119,638 bytes, dated 2026-10-05; the live file is 145,516 bytes, so restoring it would roll back eight days of Claude Code's state. Evidence: `crates/terminus/src/cmd/install/json_file.rs:423-469`.
- D-16 (Doctor): Doctor's `mcp_server` check stays a read of `~/.claude.json` and keeps its `--json` key. When `claude` is not on `PATH`, its fix prints the `claude mcp add-json` line instead of `terminus install`. Evidence: `crates/terminus/src/cmd/doctor.rs:480-631`, `docs/json-shapes.md:478-515`, phase 2 D-12.
- D-17 (Dead code): `targets::add_mcp_server` goes with its unit tests (the MCP half of `a_second_application_changes_nothing`, `another_server_is_left_alone`, `a_stale_mcp_registration_is_brought_up_to_date`). `claude_json_path` and `MCP_SERVER_KEY` stay for reads. `json_file::diff`, `align`, `line_into`, `Document::would_write` and `reformats` lose their only caller and go; `Document::overwrite` stays for the `settings.json` restore. The module comments on D-05's two files, D-06 and INST-03 are rewritten. Evidence: `crates/terminus/src/cmd/install/targets.rs:3-20,62-65,183-201,284-324,398-423`, `crates/terminus/src/cmd/install/json_file.rs:1-70,722-823`, `crates/terminus/src/cmd/install/mod.rs:1-38,365-398`.
- D-18 (Test fake): Tests stub `claude` with a fake `#!/bin/sh` script in a fixture directory given to the spawned `terminus` as `PATH`. It logs its argv and environment to a file and exits with a status the test chooses. A missing `claude` is a `PATH` without one. No override variable is added. The 21 `install --yes` calls (19 in `tests/install.rs`, 1 in `tests/uninstall.rs`, 1 in `tests/doctor.rs`) and doctor's `shell` helper change, and the tests asserting `.claude.json` edits or restores are rewritten (`tests/install.rs:754-840,891-942,1063`, `tests/uninstall.rs:252-330,442-460`). Unstubbed, the real `claude` writes `firstStartTime`, `machineID` and migration keys into the fixture config, creates `backups/`, and connects to `api.anthropic.com`. Evidence: `crates/terminus/tests/install.rs:136-146,409,572`, `crates/terminus/tests/doctor.rs:105-112`, measured 2026-10-13.
- D-19 (Docs): `DESIGN-BRIEF.md:102` (the install-time offer) and §13 at `:390-400` (the data-directory question the code never asked, diff and confirm, the offer, the `--yes` line), `docs/json-shapes.md:517-519` (the D-24 reason "They show a diff and ask a question", while the no-`--json` rule stays), new entries under `CHANGELOG.md` `[Unreleased]`, and the module comments in `install/mod.rs` and `uninstall.rs`. `main.rs` USAGE never names `--yes`. Evidence: the files named, `.planning/phases/2/PLAN-4.md:59`.

## Acceptance criteria

- [ ] AC1: With stdin closed, `terminus install` against a fake `claude` that succeeds exits 0, prints no question, and leaves the same `settings.json`, stable-path binary and `claude` call log as a run with a terminal attached; `terminus install --yes` exits 2.
- [ ] AC2: When the fake `claude` writes nothing, `~/.claude.json` is byte-identical after install, rerun and uninstall. The fake's log shows `mcp add-json --scope user terminus` with `command` set to the stable path and `args` set to `["mcp"]`, every `claude` process gets `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC=1`, a rerun with the entry already correct logs no `claude` call, and a wrong entry logs `mcp remove --scope user terminus` and then the add.
- [ ] AC3: With no `claude` on `PATH`, and again with a fake `claude` that exits 1, install still places the binary and merges the hooks, prints that the install is incomplete with the exact `claude mcp add-json` command, and exits non-zero.
- [ ] AC4: Install merges the hook entries into `settings.json` and makes one backup; a rerun leaves `settings.json` byte-identical and makes no new backup.
- [ ] AC5: The receipt lists every file changed, the backfill estimate, `terminus status` as the place to watch, the current `cleanupPeriodDays`, the line saying transcripts older than that are already gone, and the line that raises it; `cleanupPeriodDays` and `autoCompactEnabled` keep the values they had before install.
- [ ] AC6: Uninstall with a user-level entry logs `claude mcp remove --scope user terminus`, `--purge` still shows the data size and asks before deleting, with no `claude` on `PATH` `doctor` prints the `claude mcp add-json` line as the MCP fix, and `cargo test --workspace --all-features` passes.
- [ ] AC7: `DESIGN-BRIEF.md` and `docs/json-shapes.md` no longer describe an install diff, an install confirmation, install's `--yes` or an offer to raise `cleanupPeriodDays`, and `CHANGELOG.md` `[Unreleased]` records the change.

## Flagged assumptions

- `claude mcp add-json --scope user`, its "already exists" refusal and `claude mcp remove --scope user` behave the same back to doctor's `CLAUDE_FLOOR` of 2.1.227; only 2.1.296 was measured, and the owner kept the floor. - Likely; if wrong: a user on an older Claude Code gets an incomplete install with the exact command to run.
- `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` is a documented, stable Claude Code variable, and turning off nonessential traffic does not affect `mcp add-json` or `mcp remove`; measured in one traced run on 2.1.296. - Likely; if wrong: install and uninstall connect to `api.anthropic.com` through `claude`, or the variable changes what the commands do.
- Claude Code resolves a name at several MCP levels local first, then project, then user, so a leftover local or project `terminus` entry would hide the user entry install places. The owner ruled the other levels out of scope; install and doctor look only at the user level. - Likely; if wrong: nothing changes for this phase. If right and such an entry exists, doctor reports the registration fine while Claude Code uses the other entry.
- The deadline's exact value (D-07) is the planner's call, between doctor's 2 s and Baley's 30 s. - Confident; if wrong: a cold `claude` start on a slow machine is cut off and reported incomplete.
- Install reads only `claude`'s exit status and the first line of its stderr, never its stdout, whose display text has no stable format. - Confident; if wrong: a Claude Code wording change breaks install.
