# Phase 7: Blocks as rows - Context

Gathered: 2026-10-14
Feeds: /cad-plan 7

## Scope boundary

In: Each session's archive moves from one block-framed blob in `sessions.blob` to one row per block in a new archive table, keyed `(session_no, block_no)`, with the compressed bytes and a BLAKE3 hash of the uncompressed bytes. `ARCHIVE_FORMAT` goes from 1 to 2 and a format-1 store is refused. The writer, the ingest upsert and `Existing::read`, the four range readers, the five whole-session readers, `verify`, retention's evict and delete, `usage`, export's manifest and the test kit move to block rows. `DESIGN-BRIEF.md`, `docs/json-shapes.md` and the `CHANGELOG.md` Unreleased section are brought in line, and `REQUIREMENTS.md` gains STOR-08, STOR-09 and STOR-10. The owner's store is rebuilt by a clean install with the old store and binary moved aside.
Out: A conversion tool from format 1; one can come later if it is needed. The other five seeds in `.planning/CAPTURE.md` (tighten the injection gate, evict to a minimal blob, version the labels, targeted pass per hook, comments back to invariants), which stay the cycle after the install work. Changing the 64 KB block size or the zstd level. Copying `decisions` or `labels` into the new store. Checking block hashes on read. The release (phase 8) and the README (phase 9).
Deferred: None.
Plan shape: multiple plans, same phase. Suggested order: the format and the writer with ingest, then the readers, `verify` and the other consumers, then the docs and requirement rows.

## Durable decisions

- D-01 (Old-format store): `ARCHIVE_FORMAT` goes from 1 to 2, and the shared gate (`read_versions`) refuses a format-1 store for both `Store::open` and `Store::open_read_only` before any writable connection opens, so `bring_forward` never creates the block table inside an old store. This replaces STOR-05's arm that rebuilds derived tables when the archive format is older. The rebuild arm was rejected: it would add an empty block table to the old store, run `reindex`, fail every session and stamp `archive_format = 2` on a store whose only bytes sit in the old `blob` column. Evidence: `crates/terminus-core/src/store/open.rs:14,146-185,511-516,738-748`, `crates/terminus-core/src/reindex.rs:134-136,165-178,208-217`, `crates/terminus-core/tests/store_open.rs:303`; the owner's store reads `archive_format = 1` (measured 2026-10-14, read-only).
- D-02 (Clean install): The owner's clean install moves `~/.local/share/terminus/` (9.4 GB with its snapshots, measured 2026-10-14) and a copy of the current `~/.local/bin/terminus` (a plain 8,662,008-byte file from 2026-10-05, the only binary that reads format 1) aside, and does not purge them. Of the 6,570 archived sessions, 1,934 still have their transcript on disk and 4,636 do not (counted 2026-10-14 by testing each `session_meta.transcript_path`). A purge loses those 4,636 for good, and the format-1 snapshots are pruned as new ones are taken, so a conversion tool later would have nothing to convert. The owner chose moving aside over purging. Evidence: `crates/terminus/src/cmd/uninstall.rs:437-453`, `crates/terminus-core/src/ingest/pass.rs:216-225`, `crates/terminus-core/src/store/snapshot.rs:132-153`.
- D-03 (Block table): `sessions` keeps only `session_key` and `session_no` and loses its `blob` column. A new archive table holds one row per block, keyed `(session_no, block_no)`, with the compressed bytes and a 32-byte hash. It is listed in `TABLES` and never in `DERIVED_TABLES`. `session_meta` keeps `checksum` and `uncompressed_len`. Evidence: `crates/terminus-core/src/store/schema.rs:63-72,347-386`, `crates/terminus-core/src/store/open.rs:283-297`, `crates/terminus-core/src/recover.rs:163`, `crates/terminus-core/src/feedback/mod.rs:141`, `crates/terminus-core/src/inject/prompt.rs:492`.
- D-04 (Hashes): A block's hash is BLAKE3 over its uncompressed bytes, carrying v0.1.0 phase 1 D-06's reasoning down to the block. The session checksum is BLAKE3 over the block hashes in `block_no` order, stored in the existing `session_meta.checksum`. A hash over the compressed bytes was rejected because it would flag every block a later zstd version re-encodes. Evidence: `crates/terminus-core/src/blob/writer.rs:13-18`, `crates/terminus-core/src/verify.rs:3-6`, `crates/terminus-core/tests/verify.rs:124-148`.
- D-05 (Block size): The block size is recorded per session, in a `session_meta` column, and stays 64 KB (`BLOCK_SIZE`, `crates/terminus-core/src/blob/mod.rs:49`); the codec stays zstd level 3 (`ZSTD_LEVEL`, `:56`). Today each blob header carries it (`blob/mod.rs:9-28`). The owner chose per session over one store-wide `meta` key, so a later size change applies to new sessions and needs neither a rewrite nor a format bump, which D-01 would turn into a refusal. Evidence: `.planning/CAPTURE.md:24-25` (64 KB is still unmeasured).
- D-06 (Feedback history): `decisions` (4,499 rows) and `labels` (251 rows) start empty in the new store and are not copied, and `observations` (6,543 rows) regenerate only for sessions still on disk (counts measured 2026-10-14). `session_no` is assigned in ingest order, so copied rows would point at whatever session got that number in the new store. Remapping by `session_key` was rejected as a partial conversion tool. Evidence: `crates/terminus-core/src/store/schema.rs:28-48,163-167,194-207`, `crates/terminus-core/src/ingest/mod.rs:1008`, `crates/terminus-core/src/observe/mod.rs:67-110`.

## Decisions

- D-07 (Refusal message): The refusal names the clean-install steps: move the data folder and the current binary aside, then rerun `install.sh`. `terminus install` stops saying "the next hook archives the same tree" on a format-1 store, because every hook-spawned pass then fails silently. Evidence: `crates/terminus/src/cmd/install/mod.rs:333-346`, `crates/terminus/src/cmd/hook.rs:198-201`, `crates/terminus-core/src/inject/mod.rs:127-137`, `crates/terminus/src/cmd/read.rs:69-71,106`, `crates/terminus/src/cmd/doctor.rs:791-808`, `crates/terminus-core/src/error.rs:50-58`.
- D-08 (Requirements): STOR-08, STOR-09 and STOR-10 are added under `## Active` in a `### Storage (STOR)` section and replace the wording of STOR-01, STOR-03 and STOR-05, which stay under `## Shipped` as written. The Active intro's list of replaced shipped rows gains those three. `DESIGN-BRIEF.md:57,73,94,98` are rewritten to describe block rows and a refused older format. Evidence: `.planning/REQUIREMENTS.md:8-13,46-50`, `DESIGN-BRIEF.md:57,73,94,98`.
- D-09 (Eviction and deletion): An evicted session has no block rows and keeps its `checksum` and `uncompressed_len`. `delete_one` deletes block rows before the `sessions` row. Evidence: `crates/terminus-core/src/retention/apply.rs:118-140,143-190`, `crates/terminus-core/src/reindex.rs:126-133`, `crates/terminus-core/src/verify.rs:121-135`, `crates/terminus/src/cmd/export.rs:193-205`.
- D-10 (Append): An append checks only what it touches: the stored block hashes against the session checksum (32 bytes per block, no block bytes) and the tail block's bytes against its own hash. Complete blocks are neither read nor rewritten. This replaces the whole-stream check, which reads and decompresses the full session on every append, 404 blocks (26,438,881 bytes) for the largest session in the owner's store. Evidence: `crates/terminus-core/src/blob/writer.rs:57-106,108-163`, `crates/terminus-core/src/ingest/mod.rs:326-339`.
- D-11 (Existing state): `Existing::read` fetches at most the tail block row instead of the whole session for every walked file, and still runs on the writer thread. Today it selects the full blob for every walked file, unchanged ones included: 536,162,551 compressed bytes across the 1,934 sessions on disk (measured 2026-10-14). Evidence: `crates/terminus-core/src/ingest/mod.rs:159,164-169,857-871`, `crates/terminus-core/src/ingest/pass.rs:381-388`, `crates/terminus-core/src/ingest/backfill.rs:260,402`.
- D-12 (Transaction): The new block rows and the replaced tail row commit in the file's existing single transaction (STOR-02), with `prepare` and `apply` split as now. The crash harness's checks are restated over block rows: no watermark past the committed blocks, and complete blocks byte-identical across passes. Evidence: `crates/terminus-core/src/ingest/mod.rs:464-486`, `crates/terminus/tests/crash.rs:296-307,357-366,422-476,778`.
- D-13 (Readers): The range readers (`recall/excerpt.rs`, `recall/get.rs`, `recall/context.rs`, `inject/brief.rs`) fetch only the block rows a turn's `stream_offset` and `byte_len` cover. The whole-session readers (`reindex.rs`, `verify.rs`, `observe/mechanical.rs`, `cmd/export.rs`, and `prefix_matches` for flagged sessions only) fetch all of one session's rows. Turn rows keep v0.1.0 phase 1 D-04's uncompressed coordinates. Evidence: `crates/terminus-core/src/recall/excerpt.rs:98-121`, `crates/terminus-core/src/recall/get.rs:221-250`, `crates/terminus-core/src/recall/context.rs:240-262`, `crates/terminus-core/src/inject/brief.rs:519-541`, `crates/terminus-core/src/reindex.rs:165-170`, `crates/terminus-core/src/observe/mechanical.rs:267-272`, `crates/terminus/src/cmd/export.rs:185-205`, `crates/terminus-core/src/ingest/mod.rs:949-969`, `crates/terminus-core/src/store/schema.rs:50-53`, `crates/terminus-core/src/testkit.rs:438,482`.
- D-14 (Read counter): AC2 is measured by a count of block rows fetched from the database, which replaces `Reads.blobs` (a count of session blobs, `recall/excerpt.rs:58`) and sits beside `blocks_decompressed`. Evidence: `crates/terminus-core/src/recall/excerpt.rs:49-59,106`, `crates/terminus-core/src/recall/get.rs:228`, `crates/terminus-core/src/blob/reader.rs:9-15`, `crates/terminus-core/src/testkit.rs:466-498`, `crates/terminus-core/tests/recall.rs:1220,1823,2003-2117`, `crates/terminus-core/tests/inject_prompt.rs:350-526`.
- D-15 (No check on read): Readers do not check block hashes. A block that fails to decode costs its turn the body, as today, and `verify` and append are the checkers. Evidence: `crates/terminus-core/src/blob/reader.rs:55-105`, `crates/terminus-core/src/recall/excerpt.rs:61-67`, `crates/terminus-core/src/recall/get.rs:229-233`, `crates/terminus-core/src/blob/writer.rs:75-77`, `crates/terminus/src/cmd/hook.rs:211-230`.
- D-16 (Verify): For each non-evicted session, `verify` checks that the block count and numbering match `uncompressed_len` with no gaps, that each block decompresses and matches its hash, and that the session checksum matches the stored hashes. Each failure carries the session key and block number: the text line reads `<session_key>: block N: ...` and the `--json` failure gains a `block` field. Evidence: `crates/terminus-core/src/verify.rs:44-57,101-168`, `crates/terminus/src/cmd/verify.rs:14-36`, `docs/json-shapes.md:165-171`, `crates/terminus-core/src/blob/mod.rs:142-150`, `crates/terminus-core/tests/verify.rs:70-148`.
- D-17 (Other consumers): Snapshots (`VACUUM INTO`) and `data move` (a file copy) need no change. Export writes the same whole-session files and its manifest reports `archive_format` 2. `usage`'s archive bytes become the sum of each session's block byte lengths, replacing `length(s.blob)`, and `docs/json-shapes.md` follows. Evidence: `crates/terminus-core/src/store/snapshot.rs:119`, `crates/terminus/src/cmd/data.rs:297-340`, `crates/terminus/src/cmd/export.rs:236-244`, `crates/terminus/src/cmd/usage.rs:5-6,154-155`, `docs/json-shapes.md:408`, `crates/terminus-core/tests/snapshot.rs:125`.

## Acceptance criteria

- [ ] AC1: An ingest that appends to a session of at least three blocks writes its new block rows and rewrites at most its last existing block row, and every other block row of that session is byte-identical before and after. For each file it walks, the pass reads at most that session's last block row.
- [ ] AC2: Reading one turn through the excerpt, get, context and brief readers (`recall/excerpt.rs`, `recall/get.rs`, `recall/context.rs`, `inject/brief.rs`) fetches only the block rows the turn's offset and length cover, counted by the block-row counter, and decompresses only those.
- [ ] AC3: `terminus verify` reports a failure naming the session key and block number, in its text line and in a `block` field under `--json`, for each of: a block whose bytes were changed, a block row deleted from the middle of a session, and a session checksum that no longer matches the block hashes. Every other session in the same store passes.
- [ ] AC4: Every command that opens the store, run against a format-1 store, exits non-zero with a message naming the clean-install steps, and the store file's bytes are unchanged afterwards.
- [ ] AC5: On a format-2 store, `terminus reindex` gives the same query results as before the rebuild, `terminus export` writes each session's stream byte-identical to the transcript it came from (capture mode `full`) with `archive_format` 2 in its manifest, and `terminus usage` reports archive bytes equal to the sum of the block rows' lengths. `cargo test --workspace --all-features` passes, including the crash harness killing ingest at 20 or more randomized points with no watermark past the committed blocks.
- [ ] AC6: `DESIGN-BRIEF.md`, `docs/json-shapes.md` and the `CHANGELOG.md` Unreleased section describe block rows, the per-session block size, `verify`'s `block` field and the refusal of an older archive format. Neither `DESIGN-BRIEF.md` nor `docs/json-shapes.md` still says "block-framed blob" or "rebuilds derived tables only".
- [ ] AC7: On the owner's machine, with the old data folder and the current binary moved aside, a clean install ingests every session whose transcript is still on disk (1,934 on 2026-10-14), and `terminus verify` then reports no failure. (human-verify: needs the owner's real store, which the move changes)

## Flagged assumptions

- The SQLite layout for the block table is unmeasured: a rowid table against `WITHOUT ROWID` for the `(session_no, block_no)` key, the page size, and what replacing the tail row does to overflow pages in WAL mode. The analyzer measured about 62,333 blocks and 1,063,948,323 compressed bytes, roughly 17 KB a row (2026-10-14, not re-measured). The planner measures the candidates on a copy of the owner's store before choosing. - Unclear; if wrong: each append rewrites a long overflow chain or the store grows with half-empty pages, and AC1's write bound holds while the pass time does not drop.
- The 64 KB block size is still unmeasured (`.planning/CAPTURE.md:24-25`). - Unclear; if wrong: blocks are too large or too small for rows, which D-05 lets a later change fix for new sessions only.
- Whether foreign keys are enforced is stated both ways in the code: `store/schema.rs:57-58` says `PRAGMA foreign_keys` stays off, while `store/schema.rs:194-197` and `reindex.rs:127-128` say the bundled SQLite is compiled with `-DSQLITE_DEFAULT_FOREIGN_KEYS=1` and enforces them. D-09's delete order is safe either way. - Unclear; if wrong: a block table with a foreign key to `sessions` fails retention deletions only if the order in D-09 is not kept.
- The AC7 count of sessions on disk changes as Claude Code removes old transcripts and new sessions start. - Confident; if wrong: AC7 is checked against the count on the day of the clean install, not 1,934.
