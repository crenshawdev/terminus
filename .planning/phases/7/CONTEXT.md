# Phase 7: Observations - Context

Gathered: 2026-08-21
Feeds: /cad-plan 7

## Scope boundary

In: Mechanical observations for finalized sessions (files, tools, commands with arguments, errors, branch, commits, turn count, duration), always available and never involving a model; opt-in LLM judgment as exactly one call per finalized session against any OpenAI-compatible endpoint, returning strict JSON whose every claim carries a resolving `turn_id`; the parse-failure arm; cost controls; the shared credentials loader with permission enforcement; the destination-keyed egress filter; `verbatim observations regenerate`; and OBS-08 reachability through the existing three recall tools.
Out: Anthropic subscription OAuth and Anthropic's own API shape - phase 7 speaks OpenAI-compatible `chat/completions` only (D-05). Reading observations into the SessionStart resume brief - phase 5 signed off complete without it and `crates/verbatim-core/tests/inject_brief.rs:282` actively fails if any file under `src/inject/` names the string (D-19). A fourth MCP tool - OBS-08 and `DESIGN-BRIEF.md:184` both bar one. Retention, capture mode, compaction and export of observations - phase 8. Ingest-time redaction - barred by PROJECT.md.
Deferred: Anthropic subscription auth (OBS-05's "separate branch") - no OAuth flow, refresh or storage is described anywhere in the repo or on this machine, and there is no Anthropic key here to prove it against; add it as its own phase via /cad-phase when the flow is known. Windows ACL enforcement for PRIV-02 - deferred to the same later pass (D-15).
Plan shape: multiple plans, same phase

## Durable decisions

- D-01 (Store): The observations table(s) are declared in `CREATE_SQL` and listed in `schema::TABLES`, reaching already-initialized stores through `bring_forward`'s missing-table arm on the next `Store::open` - no `DERIVED_SCHEMA` bump and no forced reindex. Evidence: `crates/verbatim-core/src/store/schema.rs` (the `TABLES` comment naming phase 6 D-02), `crates/verbatim-core/src/store/open.rs` (`bring_forward` runs `CREATE_SQL` when a declared table is absent), `.planning/phases/5/CONTEXT.md` D-14. If wrong: a `DERIVED_SCHEMA` bump forces a full blob replay of the whole archive inside the ingest lock on the first hook-spawned pass after upgrade - measured at roughly 49 s over the real corpus - for a table nothing rebuilds anyway.
- D-02 (Store): Observations stay OUT of `schema::DERIVED_TABLES`, both the mechanical and the judgment halves, in one table rather than two; `verbatim observations regenerate` (OBS-07) is the only rebuild path. Evidence: `crates/verbatim-core/src/store/schema.rs` (`DERIVED_TABLES` doc, phase 6 D-03: nothing in a blob can reconstruct what was decided at the time), `crates/verbatim-core/src/reindex.rs` (drops every `DERIVED_TABLES` entry before reading a blob). This CONTRADICTS `DESIGN-BRIEF.md:64` and `:92`, which both call observations "derived"; the brief predates the `decisions`/`labels` precedent and this decision overrides its wording. If wrong: `verbatim reindex` silently deletes every purchased summary in the archive.
- D-03 (Store): The `turn_id` anchoring each generated claim (OBS-03) carries no foreign key to `turns`, matching the `labels` table. Evidence: `crates/verbatim-core/src/store/schema.rs` - the `labels` comment records that the bundled SQLite is built with `-DSQLITE_DEFAULT_FOREIGN_KEYS=1`, so a declared reference to a table `reindex` drops "would make the first `reindex` after the first label fail outright". If wrong: the first `verbatim reindex` after the first observation fails with a constraint violation, taking the derived rebuild and - since `open_up_to_date` runs on the ingest path - every subsequent ingest with it.
- D-05 (Provider): Phase 7 speaks OpenAI-compatible `chat/completions` and nothing else. One code path serves ollama and llama.cpp locally and OpenRouter, Groq, DeepSeek, vLLM or any other OpenAI-compatible endpoint remotely, with only base URL, model and API key changing. Anthropic's own API (`x-api-key`, `anthropic-version`, a different body shape) and Anthropic subscription OAuth are both out. Evidence: user decision, this pass ("it should accept an API key from anybody"); `DESIGN-BRIEF.md:332` ("Base URL is a first-class setting, not a hidden env var"); OBS-05. If wrong: OBS-05 is partially served and /cad-audit will show the gap, so the requirement row carries a note.
- D-06 (Provider): The HTTP client is `ureq` 3.4 with rustls - blocking, no async runtime, pure-Rust TLS, no system OpenSSL. This is the workspace's first HTTP dependency and its first TLS dependency. Evidence: `Cargo.lock` holds 70 packages with no `reqwest`, `ureq`, `hyper`, `rustls`, `native-tls` or `openssl`; the root `Cargo.toml` justifies each of its eight workspace dependencies against "a measured 0.408 ms startup floor" with "no async runtime, no HTTP client, no thread pool"; `cargo search` 2026-08-21 reports `ureq = "3.4.0"` current. If wrong: an async client drags a runtime into the workspace that the hook path would pay for on every cold start, which is the constraint the whole binary is built around.
- D-07 (Provider): The provider call runs OUTSIDE the ingest lock - its own command, or a step after the pass's `runs` row commits and the lock drops - never as a fourth step beside `drain`, the walk and `outcomes`. Evidence: `crates/verbatim-core/src/ingest/pass.rs` holds the OS lock for the whole pass and writes the `runs` row at the end; `crates/verbatim-core/src/ingest/lock.rs`; `crates/verbatim-core/src/feedback/mod.rs::outcomes` is the structural precedent for a post-walk step; OBS-04's "never blocks ingest". If wrong: a slow or hanging provider holds the ingest lock for the length of an HTTP call, so every hook-spawned pass in that window exits as `LockHeld` and archives nothing.
- D-13 (Egress): Whether a provider is local or remote is DECLARED, not inferred: an explicit `local = true` key in the provider block. Absent or false means remote, therefore filtered - a forgotten key fails safe toward filtering. No URL parsing, no host inspection, and no DNS resolution (which would itself be a connection PRIV-03 bars). Evidence: user decision, this pass; no URL or host-parsing code exists anywhere in the workspace and `Cargo.lock` has no `url` crate; `DESIGN-BRIEF.md:355` states the rule without saying how a provider is classified. If wrong: a user pointing at ollama and forgetting the key pays the filter unnecessarily (harmless), but a user who sets `local = true` on a reverse proxy that forwards offsite sends unfiltered data - so the key's documentation must say it means the destination, not the address.
- D-16 (Egress): The redaction boundary covers ERROR CONSTRUCTION, not just the request body. A provider or credential failure must be scrubbed before it reaches `runs.error` or stderr. Evidence: `crates/verbatim-core/src/feedback/mod.rs` documents that `Drained::discarded` and `Labeled::notes` "travel into `runs.error` with the pass's other notes" because there is no log file; `crates/verbatim-core/src/store/schema.rs` makes `runs.error` a free-text column; `verbatim status` prints it. If wrong: a malformed auth header or a 401 body carrying the key is durably stored in the archive and printed by `status` - a leak that survives, which is worse than one that scrolls past.
- D-17 (Recall): OBS-08 is served by ONE new value on the existing `kind` filter which switches `recall_search` to a second query branch over the observations table, returning hits shaped like turn hits and carrying the anchoring `turn_id`. `kind` today means `turns.record_type` with the values `user`, `assistant`, `system`, `attachment`. Evidence: `crates/verbatim-core/src/recall/search.rs::Filters::kind` compiles to `AND t.record_type = ?`; `crates/verbatim/src/cmd/mcp/tools.rs:136` documents it to the model as "Only turns of this record type: user, assistant, system or attachment"; the search SQL selects `FROM turns_fts JOIN turns` and `turns_fts` is contentless with `rowid IS turns.id`, so an observation has no natural row in it. If wrong: `kind: "observation"` is accepted and silently returns zero hits, which is indistinguishable from "nothing was found" - the worst failure mode for a recall tool.
- D-19 (Scope): The SessionStart resume brief does not read observations in this phase. Evidence: `crates/verbatim-core/tests/inject_brief.rs:282` fails if any file under `crates/verbatim-core/src/inject/` contains the string `observations`; `.planning/phases/5/PLAN-2.md:58` D-18 ("phase 7 owns the `observations` table and the brief must be complete without it"). `DESIGN-BRIEF.md:233` lists observations as a brief block, so this is a deliberate deferral of that line, not an oversight. If wrong: a green phase-5 suite turns red and the phase silently absorbs an INJ requirement already signed off complete without it.

## Decisions

- D-04 (Mechanical): OBS-01's facts are computed in SQL over `turns`, `entities`, `paths`, `compaction_boundaries` and `session_meta`, EXCEPT commands-with-arguments and commits, which require one blob read per finalized session. Evidence: `crates/verbatim-core/src/index/entity.rs::program_of` reduces a Bash command to its basename only, so `git commit -m ...` is on record as the entity value `git` with the subcommand discarded; `crates/verbatim-core/src/parse/record.rs` parses `gitBranch` and no commit field; `.planning/phases/5/PLAN-2.md` D-10 states `session_meta.branch` "is the sole git fact the archive holds". The rejected alternative was widening `entities` command normalization, which is a reindex-visible change to a shipped table. If wrong: mechanical generation reads a blob per finalized session (p90 1.0 MB, max 10.1 MB uncompressed) where it could have read none.
- D-08 (Provider): The response parser reads `choices[0].message.content` SPECIFICALLY and treats any other key on the message object as ignorable. Evidence: measured 2026-08-21, n=1, `curl` against `http://localhost:11434/v1/chat/completions` (ollama 0.32.15, `qwen3:8b`): `content` parsed as strict JSON with exactly the declared keys, but `message` carried a third non-standard key, `reasoning`, holding roughly 1 KB of chain-of-thought beside it. If wrong: a parser that stringifies the whole message object feeds reasoning prose into the JSON parse and takes the OBS-04 retry-then-`parse_failed` path on every single call against a thinking model, burning two calls per session for nothing.
- D-09 (Provider): Strict JSON is requested through `response_format: {"type": "json_schema", "strict": true}`. Evidence: the same 2026-08-21 probe - the response honored the schema and `finish_reason` was `stop`. Tool-calling (`DESIGN-BRIEF.md:326`'s alternative) is the fallback if a target endpoint rejects `response_format`.
- D-10 (Config): The provider block is a new sub-table in `verbatim.toml` (base URL, model, key reference, `local`, enable flag), parsed by `FileConfig` with unknown keys ignored, off by default. Evidence: `crates/verbatim-core/src/config.rs` - `FileConfig`'s documented rule "Unknown keys are ignored rather than rejected: this file will grow across phases"; the `[injection]` sub-table added the same way in phase 5 D-18.
- D-11 (Cost): OBS-06 splits. The daily token budget - the money-facing knob - is a config key. The minimum turn count and the truncation budget - quality knobs - stay compile-time constants. Evidence: both precedents are live in this codebase - `crates/verbatim-core/src/config.rs` promoted the injection budgets to keys (phase 5 D-18), while `crates/verbatim-core/src/feedback/finalize.rs::IDLE_HOURS` and the injection thresholds stayed compile-time (phase 6 D-08, restated in `docs/json-shapes.md` under `replay`). If wrong: either a user cannot cap what a remote provider charges them without rebuilding, or a quality threshold becomes tunable and the "one call per session" bound turns into a setting.
- D-12 (Cost): The daily token budget is durable cross-invocation state - a `meta` row holding `(date, tokens_spent)`, reset when the date changes. Evidence: `crates/verbatim-core/src/store/schema.rs` - `meta` is the only existing key/value store; the 2026-08-21 probe returned a usage object (`{"prompt_tokens":325,"completion_tokens":69,"total_tokens":394}`), so a real token count is available to accumulate. If wrong: the budget resets on every invocation and bounds nothing, because every generation is a separate short-lived process by design (no daemon).
- D-14 (Credentials): The shared-credentials loader is implemented inside this repo, not consumed from a cross-product library. Precedence is process env, then product config, then the shared file at `~/.config/jcrenshaw/credentials.toml`, namespaced by provider. Evidence: a search across `/code` for `credentials.toml` returns only `DESIGN-BRIEF.md`, `.planning/PROJECT.md` and a fixture copy - no such library exists on this machine, while `DESIGN-BRIEF.md:343` calls for one. The file does not exist on this machine either, so the loader's absent-file arm is the common case. If wrong: the phase blocks on building a separate shared crate before any observation can be generated.
- D-15 (Credentials): PRIV-02's permission refusal is a Unix mode-bit check via `PermissionsExt`; the Windows ACL check is deferred and the Windows arm accepts with a caveat surfaced in `doctor`. Evidence: `crates/verbatim/src/cmd/install/json_file.rs:1249` and `crates/verbatim-core/tests/discover.rs:245` are the only permission code in the workspace and both are `#[cfg(unix)]`-shaped `from_mode` calls; `DESIGN-BRIEF.md:341` asks for the ACL check. If wrong: a Windows user's credentials file is accepted whatever its ACL, and AC5 passes only on the platform it was tested on.
- D-18 (CLI): `verbatim observations regenerate` is the workspace's first two-word subcommand and needs a nested dispatch arm, a `docs/json-shapes.md` section, and a line in `crates/verbatim/tests/cli.rs`'s cross-command contract test. Evidence: `crates/verbatim/src/main.rs::dispatch` matches a flat set of single-word names; `crates/verbatim/src/cmd/mod.rs` states the envelope rule and that `cli.rs` holds every command to it.
- D-20 (Testing): Provider tests use a hand-rolled `std::net::TcpListener` stub speaking one canned HTTP response, including a deliberately unparseable body for the OBS-04 arm. Evidence: the project bars mocks ("real SQLite temp databases, never mocks", `DESIGN-BRIEF.md:500`); `crates/verbatim/Cargo.toml` dev-dependencies are only `verbatim-core[testkit]`, `rusqlite` and `tempfile`; `crates/verbatim-core/Cargo.toml` already gates fault injection behind the `testkit` feature the crash harness uses. If wrong: AC3 and AC4 can only be exercised against a live model, so CI has no coverage of the failure arm the requirement is entirely about.
- D-21 (Testing): AC1's and AC6's "no network connection" is proven by an in-process instrumented seam plus a source-level assertion, not an external tracer. Evidence: `crates/verbatim-core/src/discover.rs::opened` is exactly this pattern - a `testkit`-gated log with `reset`/`under`/`count`, asserted in `crates/verbatim-core/tests/pass.rs:204` to prove an excluded project was never opened; `crates/verbatim-core/tests/inject_brief.rs:282` is the source-grep precedent. Probed 2026-08-21: `strace`, `bpftrace`, `ltrace`, `tcpdump` and `docker` are all ABSENT on this machine; `ss` and `curl` are present. If wrong: the strongest privacy claim in the product ships proven only by a test that would pass if the code opened a socket through any path the seam does not wrap - so every connection must be routed through one constructor.

## Acceptance criteria

- [ ] AC1: For a finalized session with judgment disabled, `verbatim observations` lists that session's files, tools, commands with their arguments, errors, branch, commits, turn count and duration, and the instrumented network seam records zero connection attempts.
- [ ] AC2: With judgment enabled against the local endpoint, a finalized session above the minimum turn count produces exactly one HTTP request and stored JSON validating against the schema, with every `decisions`, `learned` and `unresolved` entry carrying a `turn_id` that resolves to a real turn row; a session below the minimum turn count, and any session after the daily token budget is exhausted, produce zero requests.
- [ ] AC3: Against a stub endpoint returning unparseable content, exactly two requests are made and the run is stored with `status = parse_failed` holding the raw response, and an ingest pass over the same session still completes and writes its `runs` row.
- [ ] AC4: Switching only base URL, model and key between the local endpoint and a remote OpenAI-compatible one produces a stored observation both times, with no other configuration changed. (human-verify: needs a remote OpenAI-compatible API key - none present on this machine)
- [ ] AC5: A credentials file with mode `0644` is refused with a message naming the file and its mode, no observation is generated, and no assertion over stdout, stderr, `runs.error` or the observations table finds the key's value.
- [ ] AC6: A full ingest and hook run with judgment disabled records zero connection attempts at the instrumented seam and no file outside the provider module names the HTTP client type; with `local` absent or false the request body is filtered before send, and with `local = true` it is sent unfiltered.
- [ ] AC7: `verbatim observations regenerate --since <date>` rebuilds only sessions after that date and leaves earlier rows unchanged, and `verbatim reindex` on the same store leaves every observation row present.
