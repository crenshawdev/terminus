# Phase 2: Linux and macOS Only, No npm - Context

Gathered: 2026-10-13
Feeds: /cad-plan 2

## Scope boundary

In: Terminus supports Linux and macOS only. `npm/` goes (the package, its five platform packages and `pack-local.sh`), and so does every Windows code path in `crates/`. A build for any other system fails at compile time with a message naming Linux and macOS. The docs and planning files that still describe npm or Windows are brought in line. The owner is removing Windows support from all of his products, so here it is removed outright, not deferred.
Out: Baley and the owner's other products (each removes Windows in its own repo), the install rework (phase 3), `install.sh` and how the binary copy source changes once versions sit behind the stable path (phase 4), the README (phase 5), and `windows-sys` in `Cargo.lock`, which arrives through `tempfile`, `rustix` and `errno` and is not edited by hand.
Deferred: None.
Plan shape: multiple plans, same phase. Suggested order: the code removal with the compile-time refusal and its test, then the docs and planning files.

## Durable decisions

- D-01 (Compile-time refusal): A `compile_error!` at the top of `crates/terminus-core/src/lib.rs`, guarded by `#[cfg(not(any(target_os = "linux", target_os = "macos")))]`, says "Terminus supports Linux and macOS only." It lives in core because the binary crate compiles core first, and once the guards go core uses `std::os::unix` unconditionally, so a refusal only in `main.rs` would never be reached. The guard names Linux and macOS rather than `not(unix)` so FreeBSD and other Unix systems are refused too, and criterion 2 forbids writing `target_os = "windows"` anywhere in `crates/`. With it, the other-Unix data-dir arm in `store/open.rs:896-910` and the "elsewhere" case in `config.rs:927-928` become unreachable and go. Evidence: `crates/terminus/Cargo.toml`, `crates/terminus-core/src/lib.rs`, `crates/terminus-core/src/owner_only.rs`, `crates/terminus-core/src/store/open.rs:863-910`, `crates/terminus-core/src/config.rs:927-937`, `.planning/REQUIREMENTS.md` (INST-09).
- D-02 (Windows-motivated behaviour stays): Behaviour first added because of Windows stays, and only its comments are reworded: the ISO-8601 basic-format snapshot names (the prune orders by name and existing `terminus-<time>.db` files already use the format), the ASCII `...` elision, `data move` skipping the `LOCK` copy, closing a file before the rename, and the test kit's backslash doubling (still correct JSON escaping). The user-facing message in `uninstall.rs:381-385` about removing a running file on Windows goes. Comments that describe Terminus's own Windows behaviour are reworded; comments recounting claude-mem's history (`targets.rs:26-29`, `project.rs:182`, `doctor.rs:1216`) stay. Evidence: `crates/terminus-core/src/store/snapshot.rs:24-28`, `crates/terminus-core/src/recall/excerpt.rs:44-47`, `crates/terminus/src/cmd/data.rs:147-150,172-173`, `crates/terminus-core/src/inject/decision.rs:286`, `crates/terminus-core/src/inject/state.rs:286`, `crates/terminus-core/src/testkit.rs:115-120`, `crates/terminus/src/cmd/uninstall.rs:381-385`.

## Decisions

- D-03 (Inventory): The removal works from a wider inventory than the roadmap's pattern. Besides `cfg(windows)`, `cfg!(windows)`, `target_os = "windows"`, `cfg(unix)`, `cfg(not(windows))` and `LOCALAPPDATA`, it covers `cfg(not(unix))` (`store/open.rs:438`, `tests/corpus.rs:579`, `tests/hook.rs:376`), `cfg(all(test, unix))` (`owner_only.rs:86`), and the Windows-only variables `APPDATA` and `USERPROFILE`. That is 90 lines across `crates/`, measured 2026-10-13. Evidence: `git grep` over `crates/` at 191588f.
- D-04 (Guards): Every Windows arm is deleted. Every `cfg(unix)` and `cfg(not(windows))` guard is removed and the code it guarded is kept, tests and helpers included; nothing guarded is deleted with its guard. The source sites, by what they protect: directories (`store/open.rs:888-894`, `config.rs:1041,1049-1055,1057,1066-1073`, `install/binary.rs:75-79,89,96-102`, `install/targets.rs:98,105-110`); owner-only modes (`owner_only.rs:54,78,86`, `store/open.rs:403,437-439,441,446,463`, `install/binary.rs:230`); detached spawn (`spawn.rs:64-68,137,144-148`); executable names (`project.rs:185`, `doctor.rs:577`); printed fixes (`doctor.rs:775,1253`, `install/mod.rs:479`); unit tests in `src` (`inject/decision.rs:500`, `install/json_file.rs:1193,1247`). Evidence: the files named.
- D-05 (macOS/Linux splits): The `target_os` splits that separate macOS from Linux stay two-way. Path case folding goes from `any(windows, macos)` to macOS only, so exclusions stay case-insensitive on macOS and case-sensitive on Linux. The data directory keeps its Linux and macOS arms, and so do the test helpers that mirror it. Evidence: `crates/terminus-core/src/config.rs:927-937`, `crates/terminus-core/src/store/open.rs:863,877`, `crates/terminus/tests/datamove.rs:73`, `crates/terminus/tests/owner_only.rs:83`, `DESIGN-BRIEF.md:356`.
- D-06 (Proving the refusal): A test in the suite asserts the D-01 guard and message are present in core's `lib.rs`. The real Windows build is a human check on a Windows machine. This machine has only the `x86_64-unknown-linux-gnu` std and no mingw compiler, and a cargo cross-build would also need one for the bundled SQLite and zstd. Evidence: `rustup target list --installed` (2026-10-13), `Cargo.toml` (`rusqlite` bundled, `zstd`), `crates/terminus-core/tests/no_network.rs` (the source-scan pattern Phase 1 used), v0.1.0 phase 4 precedent (AC3's Windows half stayed a human check).
- D-07 (Tests): No test that covers only Windows remains; Phase 1 removed the last ones. The phase summary lists what is removed from tests instead: the `#[cfg(not(unix))] fn drain` stubs (`tests/corpus.rs:579-580`, `tests/hook.rs:376-377`), the `terminus.exe` arms (`tests/doctor.rs:92`, `tests/hook.rs:74`, `tests/install.rs:111`, `tests/uninstall.rs:99`), the `LOCALAPPDATA` arms (`tests/datamove.rs:7,71-72,102`) and the `USERPROFILE` lines (`tests/datamove.rs:104`, `tests/doctor.rs:116`, `tests/install.rs:149`, `tests/uninstall.rs:128`). Every `#[cfg(unix)]` test and helper keeps its body. Evidence: the files named, `.planning/phases/1/PLAN-2.md`.
- D-08 (`install/binary.rs`): Only its doc comments change: the npm paragraph at 16-20 and the `%LOCALAPPDATA%` line at 5-6. It keeps copying from `std::env::current_exe()` (`binary.rs:186`); phase 4 decides whether that changes. Evidence: `crates/terminus/src/cmd/install/binary.rs`.
- D-09 (Docs and planning files): Brought in line: `.gitignore:5-11` (the npm block); `DESIGN-BRIEF.md`'s Windows text (`:121`, `:129`, the Windows column and line in §12 at `:362-366` and `:374`, case-folding at `:152` and `:356` narrowed to macOS, the CI row at `:461`, the open item at `:488`) and §13 (`:380-390`, `:408`), reworded to say there is no npm channel and the installer arrives in phase 4, without designing it; the v2 Distribution note at `REQUIREMENTS.md:120`; `PROJECT.md`'s Compatibility and Distribution constraints (`:104`, `:107`), its npm and Windows decision rows (`:120`, `:132`) and the Windows open item (`:96`), plus a new decision row saying Windows is dropped across all of the owner's products. `CAPTURE.md`'s npm items (`:102`, `:107-113`), its Publish milestone (`:204-292`) and the Windows items in it are closed as no longer applicable. `ROADMAP.md`, the INST-01 and INST-09 rows, `PROJECT.md`'s shipped-cycle tables (`:35`, `:55`), `ARCHIVE.md`, `.planning/phases/` and `reads.jsonl` stay as they are. Facts about claude-mem in `DESIGN-BRIEF.md` (`:22`, `:119`) stay. Evidence: the files named.
- D-10 (CHANGELOG): `[Unreleased]` gets Removed entries for the npm package and for Windows support. The `%LOCALAPPDATA%\terminus` clause in the unreleased rename entry (`CHANGELOG.md:17-18`) is dropped, since that path never ships. The Verbatim 0.1.1 line about the Windows deferral (`:89-90`) stays as release history. Evidence: `CHANGELOG.md`.
- D-11 (Windows ACL deferral): v0.1.0 phase 7's D-15 already left `doctor` in Phase 1 (efabb2d). What remains goes: the `owner_only.rs:12-22` module doc that still says doctor states the deferral, and the no-op Windows `tighten` arm at `store/open.rs:437-439`. `CAPTURE.md:294-311`'s icacls proposal is closed as no longer applicable, and the closure is recorded there. The PRIV-02 row (`REQUIREMENTS.md:87`) stays as written. The closure targets that decision by its content, never by a search for "D-15", which labels about 40 other decisions in `crates/` comments (lock, config, snapshot, replay). Evidence: `crates/terminus-core/src/owner_only.rs`, `crates/terminus-core/src/store/open.rs`, `crates/terminus/src/cmd/doctor.rs`, `.planning/CAPTURE.md`, `crates/terminus-core/src/ingest/lock.rs`.
- D-12 (Doctor): Doctor prints nothing about Windows and gets no platform check. Its `attrib`, `del` and `claude.exe` branches go, leaving `chmod u+w`, `rm -f` and `claude`. A platform check would always pass on a binary that only builds on Linux and macOS, and the `--json` key set is a contract. Evidence: `crates/terminus/src/cmd/doctor.rs:138-142,577,775,1253`, `docs/json-shapes.md:507-509`, `crates/terminus/tests/doctor.rs:672-710`.
- D-13 (CI): No CI or release configuration exists to change: no `.github/` or `.forgejo/`, no Makefile or justfile, and no `[target.'cfg(windows)']` section in any `Cargo.toml`. The only build script, `npm/pack-local.sh`, goes with `npm/`. Evidence: repo root listing, `Cargo.toml`, `crates/*/Cargo.toml`.

## Acceptance criteria

- [ ] AC1: `npm/` is gone. `git grep -i npm` over `crates/`, `docs/`, `Cargo.toml` and `.gitignore` finds nothing, and `DESIGN-BRIEF.md`, `PROJECT.md` (outside its shipped-cycle tables) and `REQUIREMENTS.md` (outside the INST-01 and INST-09 rows) name npm only to say it was removed.
- [ ] AC2: `git grep -E` over `crates/` finds no `cfg(windows)`, `cfg!(windows)`, `target_os = "windows"`, `cfg(not(windows))`, `cfg(unix)`, `cfg(not(unix))`, `cfg(all(test, unix))`, `LOCALAPPDATA`, `APPDATA`, `USERPROFILE` or `.exe"` string literal.
- [ ] AC3: `crates/terminus-core/src/lib.rs` carries a `compile_error!` guarded by `not(any(target_os = "linux", target_os = "macos"))` with the message "Terminus supports Linux and macOS only.", and a test in the suite fails if the guard or the message is removed.
- [ ] AC4: On a Windows machine, `cargo build` of Terminus fails and its output contains "Terminus supports Linux and macOS only." (human-verify: needs a Windows machine with Rust)
- [ ] AC5: `cargo test --workspace --all-features` passes and lists 749 tests, the count measured 2026-10-13 before the phase, and the phase summary lists every test helper and `.exe` arm removed.
- [ ] AC6: `terminus doctor`, `terminus doctor --json` and `terminus uninstall` print no `attrib`, `del` or `.exe` fix and no mention of Windows, and `doctor --json` carries the same top-level keys it does before the phase.
- [ ] AC7: `DESIGN-BRIEF.md` and `PROJECT.md` name Linux and macOS as the supported systems, every remaining mention of Windows in them is about claude-mem or says Windows was dropped, and `CAPTURE.md`'s npm items, Windows items and icacls proposal are marked closed as no longer applicable.

## Flagged assumptions

- Whether cargo on a Windows machine with MSVC shows the `compile_error!` text first or among the unresolved `std::os::unix` errors is unknown; only a real Windows build shows it. - Likely that it appears; if wrong: AC4 fails and the refusal needs to sit where it is reached before the unresolved imports, for example a `build.rs`.
- Whether cc-rs falls back to another compiler or fails outright for `x86_64-pc-windows-gnu` on a Linux host without mingw is not researched. D-06 sidesteps it by not cross-building here. - Likely; if wrong: nothing changes for this phase.
- The 749 baseline is the `cargo test --workspace --all-features -- --list` count of `: test` lines on Linux at 191588f. Removing `cfg(unix)` guards should not change it, because those tests already run on Linux. - Likely; if wrong: the count moves, and the summary has to account for each test gained or lost.
- How `CAPTURE.md` items are marked closed (checked box, a note, or both) is the planner's call. - Confident; if wrong: the closure is harder to find, nothing else.
