Deviations:
- [deviation] Task 6 says opening a store with a lower `derived_schema`/`archive_format` runs the rebuild and updates `meta`. PLAN-1's committed `crates/verbatim-core/tests/store_open.rs::an_older_derived_schema_opens_with_a_rebuild_outcome` asserts the opposite, and that file is not in this plan's `files:` list. Resolved the preferred way: `Store::open` stays side-effect-free and reports the outcome, `reindex::open_up_to_date` is the caller that acts on it (rebuild, then reopen so the handle reports what the store now carries), and `ingest` goes through it. No file outside the lease was touched and PLAN-1's test still passes unchanged. `verify` deliberately keeps the plain open: it is the command you run on a damaged store, and a rebuild that a corrupt blob would fail must not stand in front of the diagnosis.
- [deviation] Tasks 5 and 6 put process-level assertions (`verbatim verify`'s exit code and stdout, `verbatim reindex` invoked as a command) in `crates/verbatim-core/tests/`. That crate cannot spawn the binary: `CARGO_BIN_EXE_verbatim` is defined only for integration tests of the package declaring the bin, and `verbatim-core` does not depend on `verbatim`. Library-level assertions stayed in `crates/verbatim-core/tests/{verify,reindex}.rs`; the process-level ones moved to a new `crates/verbatim/tests/cli.rs` with no hardcoded `target/debug/verbatim`. That path was added to PLAN-2.md's `files:` frontmatter, with a comment saying why, so the lease gate reflects reality; the plan file is left modified for the orchestrator's docs commit.
- [deviation] AC3 says "prints that session id, and prints no other session id", and no task pinned whether that is `session_key` or the record-reported `session_id`. D-01 establishes the latter is not unique - `subagents/agent-alpha.jsonl` deliberately reports `session-basic`'s sessionId - so a report keyed on it makes the "and no other" clause unfalsifiable. `verify` names sessions by `session_key`, the canonical transcript path and the primary key of `sessions`. Both the library and the CLI test ingest the colliding pair, and the CLI test corrupts the *sidecar*, so naming its parent would fail.
- [deviation] AC5's CLI half was asserted nowhere: no task ran any command against a store whose `archive_format` is one above the binary's. `crates/verbatim/tests/cli.rs` now runs both `verbatim verify` and `verbatim ingest` against a hot-WAL copy of such a store and asserts a non-zero exit, a stderr message naming both versions, and byte-identical `verbatim.db`, WAL, `runs` and `meta`.
- [deviation] Task 7's harness had no mechanism for landing a kill inside the ingest transaction (an uninterrupted release pass over the 5 MB corpus measures 15 ms, and over a few-KB fixture is single-digit milliseconds), and asked for the negative confirmation as a manual edit-and-revert. Both changed. `crates/verbatim-core/src/ingest/mod.rs` (in the plan's `files:` list, though not task 7's) grew a `fault` module: six named points where a `testkit`-gated build announces its arrival through a file the parent polls and then waits to be SIGKILLed, plus a switch that commits the watermark in a transaction of its own before the pass. `crates/verbatim/Cargo.toml` grew a `testkit` feature that turns those points on in the binary under test. The negative is now a recorded test - `the_harness_catches_a_watermark_committed_outside_the_transaction` - which kills at the split point and requires the invariant check to reject the result, with a control killing at the equivalent in-transaction moment and requiring acceptance. The shipped `cargo build --release` binary has no such branch, confirmed by running it with the fault variables set: it completed in 1 ms and created no marker.

Open items:
- `crates/verbatim-core/src/store/schema.rs` documents that foreign keys are "deliberately not enforced: `PRAGMA foreign_keys` stays off, because `reindex` drops the derived children wholesale and enforcement would only dictate a drop order". They are enforced: libsqlite3-sys-0.38.1/build.rs:126 compiles the bundled amalgamation with `-DSQLITE_DEFAULT_FOREIGN_KEYS=1`, and a `DROP TABLE turns` with rows in `paths` fails with a constraint violation. `reindex` handles it by dropping in reverse creation order, which is exactly the drop order the comment says enforcement "would only dictate", but the comment is wrong and the file is outside this plan's lease.
- `session_meta.continues_from` is populated in the session-id namespace: the record's foreign `session_id` when present, otherwise the first turn's `parentUuid` resolved through `turns` to the session that holds that record. D-11 does not say which namespace the fallback writes, and the fallback depends on the predecessor already being ingested. Phase 2 (ING-04) consumes the column and should confirm the choice.
- The crash harness passes both with and without `--features testkit`, because the `verbatim-core` dev-dependency's feature unifies into the bin build under `cargo test -p verbatim`. The explicit `cargo test -p verbatim --release --features testkit --test crash` is the invocation to put in CI; relying on unification would make the harness silently vacuous if the dev-dependency ever changed.
