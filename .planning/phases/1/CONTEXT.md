# Phase 1: No Model Calls - Context

Gathered: 2026-10-13
Feeds: /cad-plan 1

## Scope boundary

In: Terminus stops calling a model and handling an API key, and opens no network connection. The judgment half of observations goes with everything that exists only for it: `observe/judgment.rs`, `observe/provider.rs`, `observe/net.rs`, `observe/cost.rs`, `credentials.rs`, the `[provider]` table and its accessors in `config.rs`, the `ureq` dependency, the test kit's HTTP stub, `doctor`'s key, config-permission and provider checks, and the 2,529 summaries already stored, with recall's `kind: observation` filter that only ever searched them. The mechanical half of observations stays, and so do the shape rules in `observe/egress.rs` that `redact_recall` uses.
Out: Windows code (phase 2), install behaviour (phases 3 and 4), README (phase 5), moving `egress.rs` out of `observe/`, re-pointing `kind: observation` at the mechanical facts, and any network use the later update feature will need.
Deferred: None.
Plan shape: multiple plans, same phase. Suggested order: config refusal and doctor; the judgment, provider, network and cost code with `ureq` and the test kit stub; the summary column drop with recall's observation filter; the redaction test reroute and the docs.

## Durable decisions

- D-01 (Stored summaries): The 2,529 stored summaries are dropped. The ten judgment columns (`status`, `model`, `prompt_version`, `topic`, `outcome`, `decisions`, `learned`, `unresolved`, `raw`, `tokens`) are removed from `observations` in a one-time store change, and `CREATE_SQL` changes to match so a fresh store and an upgraded one have the same columns. The row stuck at `judging` and the meta key `observe.daily_tokens` go with them. Recall's `kind: observation` branch, `CLAIMS`, `OBSERVATION_KIND`, `Reason::NoObservations` and the MCP `kind` description go, and so does `observations regenerate --prompt-version`. `export` is unaffected; it never exported observations. The three rolling snapshots keep the dropped text for about three days. The owner chose this over keeping them frozen: he does not use them, they would never grow, and they were 31.1M tokens of `gpt-5.4-mini` output from one run on 2026-09-12. Evidence: `crates/terminus-core/src/store/schema.rs:233-253,430-433`, `crates/terminus-core/src/store/open.rs:480-489,701-719`, `crates/terminus-core/src/recall/search.rs:30-37,351-356,464-642`, `crates/terminus-core/src/recall/scope.rs:88-114`, `crates/terminus/src/cmd/observations.rs:83-86,194-207,288-304`, `crates/terminus/src/cmd/mcp/tools.rs:136-143`, `docs/json-shapes.md:252-300`, owner's store read 2026-10-12 (2,512 ok, 17 parse_failed, 1 judging).
- D-02 (Observations stay archival): `observations` stays out of `DERIVED_TABLES` and `reindex` keeps never touching it. The reason changes from "a paid model call" to: the mechanical facts come off the session blob, and retention eviction empties that blob, so an evicted session's observation cannot be recomputed. Evidence: `crates/terminus-core/src/store/schema.rs:210-217,395-411`, `crates/terminus-core/src/observe/mechanical.rs:17-25,267-273`, `crates/terminus-core/src/retention/apply.rs:55-60`, `crates/terminus-core/src/reindex.rs:30-33`.

## Decisions

- D-03 (Criterion 4): The roadmap's "recall still finds it" is read as: `terminus observations` still lists a session's mechanical observation, and its files, commands and errors stay searchable through the turn index (`paths`, `entities`, `turns_fts`). Recall has never searched the mechanical document. Evidence: `crates/terminus-core/src/recall/search.rs:503-631`, `crates/terminus-core/src/observe/mechanical.rs:68-114`.
- D-04 (`[provider]` refusal): Any top-level `provider` key in `terminus.toml` fails `Config::load_from`, whether a full table, an empty one or one with `enabled = false`. The check runs after a successful parse against a captured field that is never read into values, and it carries its own error naming the path and saying model calls were removed, not `Error::ConfigParse`, whose text says the file is not valid TOML. It is the first deliberate exception to "unknown keys are ignored". It applies to every `Config::load` caller, hooks included: hook injection returns nothing and the hook-spawned pass exits before writing a `runs` row, so archiving stops until the table is removed, shown by `terminus status` and `doctor`'s `config_roots`. The owner has no `~/.config/terminus`. Evidence: `crates/terminus-core/src/config.rs:81-116,627-647`, `crates/terminus-core/src/error.rs:142-149`, `crates/terminus/src/cmd/hook.rs:238-255`, `crates/terminus-core/src/ingest/pass.rs:130-132`, `crates/terminus/src/cmd/doctor.rs:668-684`.
- D-05 (Doctor): `doctor` loses `credentials`, `config_mode`, `mode_checks` and `provider_local`, with `provider_local`'s `unknown` arm, `host_of` and `is_loopback`, and their tests. Evidence: `crates/terminus/src/cmd/doctor.rs:139-147,672,681,714-835,838-960,1505-1565`, `crates/terminus/tests/doctor.rs:820-1260`.
- D-06 (Redaction): `observe/egress.rs` keeps its shape rules, `for_model_context` and `Redaction`. Rule 1 (`replace_credential`, `REDACTED_CREDENTIAL`, `MIN_CREDENTIAL_CHARS`) and the `Secret` parameter lose their only source and go, as do `for_destination` (only caller `provider.rs:293`) and `scrub` (callers only in `judgment.rs`, `provider.rs`, `observe/mod.rs`). `Redaction::of` passes no exact key. "The same rules" in criterion 5 means the shape rules. The module stays at `observe/egress.rs`. Evidence: `crates/terminus-core/src/observe/egress.rs:15-21,202-242,266-299,336-344`, `crates/terminus-core/tests/egress.rs:44-220`.
- D-07 (Redaction proof): The `wire` module's `PLANTED` table in `tests/egress.rs`, including `every_planted_shape_is_gone_and_its_rule_named_itself`, is rerouted through a recall projection with `redact_recall` on instead of `judgment::judge` and `HttpStub`. It is the only test tying each sentinel in `session-secrets.jsonl` to its rule's marker over a really ingested transcript. Evidence: `crates/terminus-core/tests/egress.rs:254-724`, `crates/terminus-core/tests/redacted_recall.rs:139-197`.
- D-08 (No network, enforced): Removing `ureq` from the root `[workspace.dependencies]` and `crates/terminus-core/Cargo.toml` removes every HTTP and TLS crate (rustls, ring, webpki-roots, http, httparse, ureq-proto arrive only through it; no hyper or reqwest is present, measured 2026-10-12). The test kit's `HttpStub`, `http_response`, `chat_completion` and `std::net` import go; `testkit.rs` is the only `src/` file besides `net.rs` that opens a socket. A source-scan test enforces "opens no network connection" from then on, the way `tests/egress.rs` already scans for the ingest path. `net::attempts` and the loopback-stub tests go with `net.rs`. The redaction fixtures keep `OPENAI_API_KEY=` and `"api_key"` as input text. Evidence: `Cargo.toml`, `crates/terminus-core/Cargo.toml`, `crates/terminus-core/src/testkit.rs:549-730`, `crates/terminus/tests/observations.rs:726-766`, `crates/terminus-core/tests/egress.rs:26,97,231-252`.
- D-09 (Docs): `DESIGN-BRIEF.md`'s shared-credentials section (334-343) and its observation-judgment text, `docs/json-shapes.md`'s observation shapes, the `Cargo.toml` comments about `ureq` and `toml`, a Removed entry under `CHANGELOG.md` `[Unreleased]`, and the `CAPTURE.md` items that verify remote observations are brought in line. The shipped PRIV-02 and OBS-02 to OBS-06 rows stay as written. Evidence: `DESIGN-BRIEF.md:334-343`, `CHANGELOG.md:7`, `.planning/REQUIREMENTS.md:9-13`, `.planning/CAPTURE.md:134`.

## Acceptance criteria

- [ ] AC1: `cargo tree -e all --target all` over the workspace lists no `ureq`, `reqwest`, `hyper` or `rustls`, and a test fails if any file under `crates/*/src` names `std::net`, `TcpStream`, `TcpListener` or `UdpSocket`.
- [ ] AC2: A source scan finds no environment lookup of an `_API_KEY` name and no `credentials.toml` path outside the redaction test fixtures.
- [ ] AC3: A `terminus.toml` with a `[provider]` table, either empty or holding `api_key = "<sentinel>"`, makes `terminus status` exit non-zero with a message naming the file and saying model calls were removed, and the sentinel appears in neither stdout nor stderr.
- [ ] AC4: A store carrying the old summary columns opens with none of the ten left (`PRAGMA table_info(observations)`), every row's mechanical document is byte-identical to before, `terminus verify` passes, and a fresh store's `observations` columns equal the upgraded store's.
- [ ] AC5: A session finished after the change gets a mechanical observation that `terminus observations` lists, `terminus search` finds its files, commands and errors, and `recall_search` no longer offers `kind: observation` and its description no longer mentions summaries.
- [ ] AC6: With `redact_recall` on, every secret planted in `session-secrets.jsonl` is absent from `recall_search` excerpts, `recall_context`, `recall_get` and the `SessionStart` brief, and each rule's marker appears in its place.
- [ ] AC7: `terminus doctor --json` carries no `credentials`, `config_mode`, `mode_checks` or `provider_local` key, and `cargo test --workspace --all-features` passes.

## Flagged assumptions

- `withhold_secret_excerpt` stays: a malformed key line inside a leftover `[provider]` table fails the parse before the D-04 refusal can run, and the parser's excerpt would print it (`crates/terminus-core/src/config.rs:629-638,1325-1345`, `crates/terminus-core/tests/config.rs:177`). Kept by default, not confirmed as a decision. - Likely; if wrong: an unquoted key in a leftover file prints on stderr from every command that loads config.
- How the column drop is recorded so it runs exactly once on an existing store is the planner's call: `bring_forward` is documented additive-only and `ARCHIVE_FORMAT` bumps force a full derived rebuild of a 2.4 GB store, so a dedicated marker is likely the cheaper route. SQLite 3.53.2 (bundled, libsqlite3-sys 0.38.2) supports `ALTER TABLE DROP COLUMN`. - Likely; if wrong: an `ARCHIVE_FORMAT` bump rebuilds every derived table on the owner's store for a change to one non-derived table.
- What a caller passing the retired `kind: "observation"` gets back is the planner's call, within phase 7 D-17's rule that an accepted kind silently returning zero hits is the worst outcome: refuse it by name rather than return nothing. - Likely; if wrong: an MCP client or old prompt asking for observations gets a silent empty answer.
- The `egress.rs` module doc says feedback notes are scrubbed, but no feedback file calls `scrub`; the doc is corrected when `scrub` goes. - Confident; if wrong: the doc keeps describing a scrub that never ran.
- Whether `toml` 1.x's excerpt for a serde custom error on a table-valued field would include lines inside `[provider]` is not researched. D-04 sidesteps it by refusing after the parse, not during deserialization. - Likely; if wrong and the refusal is moved into deserialization, a key value can reach the message.
