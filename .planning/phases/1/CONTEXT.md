# Phase 1: Archive Core - Context

Gathered: 2026-08-12
Feeds: /cad-plan 1

## Scope boundary

In: The SQLite store and its schema, the block-framed zstd blob format with per-blob checksums, single-transaction ingest of one named transcript file, byte-offset tailing with crash recovery, OS try-lock exclusivity, format-version gating, `verbatim verify` and `verbatim reindex`.
Out: Transcript-tree discovery, subagent sidecar walking, project identity from `cwd`, exclusions, compaction boundaries, `verbatim status` (all phase 2). Rust-side text expansion, entity extraction, search and the MCP tools (phase 3) - phase 1 creates the FTS and entity tables and their rebuild path, but not what fills them. Hooks, install and backfill (phase 4).
Deferred: None - the size check kept all seven criteria in this phase.
Plan shape: multiple plans, same phase

## Durable decisions

- D-01 (Archive identity): `sessions` is keyed on the transcript file identity, not on `session_id` alone. Evidence: measured against `/data/claude/.claude/projects` - 812 sidecar files under 228 `subagents/` dirs, every record reporting the parent session's `sessionId`, plus 38 files one layer deeper under `subagents/workflows/wf_*/`; `DESIGN-BRIEF.md:57`, `DESIGN-BRIEF.md:141`. If wrong: every subagent file collides with its parent on insert, or silently overwrites the parent's blob with a 3 KB agent transcript.
- D-02 (Archive identity): `turns.turn_seq` is assigned from byte order within the transcript file, never from sorting on `timestamp`. Evidence: 31 of 62 sampled transcripts contain at least one out-of-order timestamp; `uuid` is unique within every sampled file; `DESIGN-BRIEF.md:62` leaves the source unstated. If wrong: roughly half of all sessions get scrambled neighbours, and `reindex` reproduces the same wrong order on both sides so AC4 still passes.
- D-03 (Turn shape): A turn is a record carrying both `uuid` and `timestamp` - types `user`, `assistant`, `attachment`, `system`. The other eleven record types (`last-prompt`, `ai-title`, `mode`, `permission-mode`, `file-history-snapshot`, `queue-operation`, `bridge-session`, `file-history-delta`, `agent-name`, `agent-setting`, `frame-link`) are stored verbatim in the blob and produce no turn, FTS or entity row. Evidence: 5,260 of 6,731 sampled records carry the full identity set; all 129 `file-history-snapshot` records carry no `sessionId` at all, contradicting `DESIGN-BRIEF.md:144`.
- D-04 (Blob format): `turns` stores an uncompressed-stream offset and length; the blob header holds the block offset table and translates. Evidence: `DESIGN-BRIEF.md:73` specifies the header contents but not what `turns.offset` addresses; `DESIGN-BRIEF.md:94` forbids migrating the archive table. If wrong: a future block-size change rewrites every turn row, which is what "the archive table never migrates" exists to prevent.
- D-05 (Blob format): A turn maps to a range of blocks, not to exactly one. STOR-01 means one block for turns that fit in one block. Evidence: 28 of 6,731 sampled records exceed 65,536 bytes, 3 exceed 1 MB, max 1,134,645 bytes.
- D-06 (Integrity): Per-blob checksum is BLAKE3 over the uncompressed session bytes, stored in `session_meta`; `verify` decompresses to check it. Evidence: `DESIGN-BRIEF.md:98` requires a checksum independent of SQLite's own integrity checks and of the codec. If wrong: a codec-level bug or format bump invalidates every stored checksum and `verify` cannot distinguish corruption from a decoder change.
- D-07 (Ingest writes): Completed 64 KB blocks are immutable once committed; only the partial trailing block is recompressed and rewritten on each pass. Evidence: p90 session is 1.0 MB and max is 10.1 MB across 1,221 top-level transcripts; `DESIGN-BRIEF.md:116` notes `SessionEnd` does not fire on a crash, so live sessions are re-ingested repeatedly while growing. If wrong: a long session is recompressed dozens of times and the WAL grows by the full blob size on every pass.
- D-08 (Compression): zstd level 3 is the default, and the brief's "~2 GB/year compressed" figure is corrected to ~3.1 GB/year. Evidence: measured on block-framed real transcripts - level 3 = 4.21x, level 9 = 4.49x, level 19 = 4.80x, against the ~6.5x implied by `DESIGN-BRIEF.md:75`; whole-stream level 3 reaches 4.31x, so random-access framing costs 11.2%. No zstd dictionary: it would become part of the archive format that never migrates.
- D-09 (Versioning): Two integers in a `meta` key/value table - `archive_format` and `derived_schema` - both read before any write to the store. Evidence: `DESIGN-BRIEF.md:511` requires the store format version to be a separate integer from the product version; `DESIGN-BRIEF.md:94` separates the archive from derived tables. If wrong: one integer cannot distinguish "derived tables need a rebuild" from "the archive itself changed", collapsing the distinction STOR-05 turns on.
- D-10 (Derived tables): `turns_fts` is contentless (`content=''`, `contentless_delete=1`) and its rowid is a deterministic `turns.id` derived from `(session_key, turn_seq)`, so a rebuild is idempotent by construction. Evidence: `DESIGN-BRIEF.md:60`, `DESIGN-BRIEF.md:77`. If wrong: a rebuild renumbers every FTS row and AC4's fixed query set returns hits pointing at different turns while returning the same count.
- D-11 (Session lineage): `session_meta` carries a `continues_from` column populated from the record's foreign `session_id` field, which is the reliable file-level lineage signal. `parentUuid` stays a per-turn column recording message-level threading within one conversation, and serves as the lineage fallback only when a continuation file carries no foreign `session_id`. Neither replaces the other. Evidence: measured - 187 of 1,221 top-level transcripts (15.3%) carry a `session_id` naming a different existing sibling transcript, an order of magnitude above the 1.2% `parentUuid` resume rate in `DESIGN-BRIEF.md:143`. Phase 2 (ING-04) consumes the column; phase 1 defines it.

## Decisions

- D-12 (Parsing): The parser tolerates `.jsonl` files in the tree that are not transcripts; discovery filters by filename pattern (`<uuid>.jsonl`, `agent-*.jsonl`) rather than by record shape at parse time. Evidence: four `journal.jsonl` files under `subagents/workflows/wf_*/` hold `{agentId, key, result, type}` records with no `sessionId`, `uuid`, `timestamp` or `cwd`; `DESIGN-BRIEF.md:141` mandates recursive discovery with `dot: true`, which reaches them.
- D-13 (Blob content): The blob holds the raw transcript bytes verbatim, not a parsed projection. Evidence: `DESIGN-BRIEF.md:92`, `DESIGN-BRIEF.md:94`, `DESIGN-BRIEF.md:353`. Restates a PROJECT.md key decision at schema level: a phase 3 change to extraction must be replayable against the original bytes, or FEED-03's offline replay has nothing faithful to replay against.
- D-14 (Watermark): The watermark is the byte offset just past the last `\n` in the transcript, never end-of-file. Evidence: all 1,221 top-level and 812 sidecar transcripts end with `\n`; zero `\r` bytes in the first 200 files; 0 unparseable lines in 11,332 records across 103 sampled files, matching `DESIGN-BRIEF.md:142`.
- D-15 (Exclusivity): A dedicated `LOCK` file in the data directory with an OS try-lock (`flock(2)` with `LOCK_NB`, `LockFileEx` with `LOCKFILE_FAIL_IMMEDIATELY`), never `BEGIN EXCLUSIVE`. Evidence: `DESIGN-BRIEF.md:48-53`, `DESIGN-BRIEF.md:127`, `DESIGN-BRIEF.md:135`. If wrong: the second process blocks on SQLite's busy handler and blows the 50 ms budget, or holds a write transaction open for the whole pass and stops MCP readers - the reason redb was rejected at `DESIGN-BRIEF.md:83`.
- D-16 (Verify scope): `verify` walks blob checksums only. `PRAGMA integrity_check` is a separate signal owned by `doctor` (INST-06). Evidence: `DESIGN-BRIEF.md:98-99`, `DESIGN-BRIEF.md:470`. If wrong: a page-level `integrity_check` complaint with no session attribution rides alongside the named session and AC3's "no other" fails on a store that is otherwise fine.
- D-17 (Layout): A cargo workspace - `verbatim-core` (store, blob, ingest) and `verbatim` (CLI, later the MCP server) - with `rayon` and any HTTP client feature-gated off the hook-path build. Evidence: no `Cargo.toml` exists; `DESIGN-BRIEF.md:37-39` requires a single static binary with no async runtime, `DESIGN-BRIEF.md:498` makes hook cold start an asserted CI budget, `DESIGN-BRIEF.md:504` requires tests against real temp SQLite databases.
- D-18 (Ingest interface): Phase 1 ships `verbatim ingest <path.jsonl>` taking one explicit file; the no-arg tree walk arrives in phase 2. Evidence: `ROADMAP.md:21` scopes phase 1 to one transcript; `DESIGN-BRIEF.md:478` lists only the no-arg form. Keeps the crash and lock-race tests (AC2, AC6) on a small fixture rather than the real 962 MB tree.
- D-19 (Dependencies): `rusqlite` pinned to the current release (>= 0.32, whatever cargo resolves) with features `["bundled", "fts5"]`. Two separate facts: the bundled amalgamation has shipped SQLite >= 3.45 since early 2024 (3.49+ current), above the 3.43 floor `contentless_delete=1` needs; and FTS5 is not compiled in by `bundled` alone, it requires the `fts5` cargo feature. Both are asserted at first store open in CI - `SELECT sqlite_version()` plus creating a scratch `contentless_delete=1` FTS5 table.
- D-20 (Locks off Linux): Immediate-fail try-lock holds on every target. APFS honors `flock(2)` with `LOCK_NB`; the Windows path is filesystem-agnostic byte-range locking, so NTFS versus ReFS does not matter. Container overlayfs is safe here because verbatim creates the `LOCK` file itself in its own data directory, on the upper layer as a single inode - the historical overlayfs `flock` hazard is pre-copy-up shared inodes, which cannot arise for a file the process creates.

## Acceptance criteria

- [ ] AC1: Ingesting a fixture transcript and then reading a turn that fits inside one block decompresses exactly 1 block, and reading a turn spanning N blocks decompresses exactly N, both counted by an instrumented reader.
- [ ] AC2: A harness that kills ingest at 20 or more randomized points and then reopens the store finds, for every session, turn, FTS and entity rows only where a blob with a matching BLAKE3 checksum exists, and no watermark past the last committed block boundary.
- [ ] AC3: `verbatim verify` on a store with one byte flipped inside one session's blob exits non-zero, prints that session id, and prints no other session id.
- [ ] AC4: Dropping `turns`, `turns_fts` and the entity tables and then running `verbatim reindex` produces byte-identical `--json` output for a fixed query set, compared before and after.
- [ ] AC5: Opening a store whose `meta.archive_format` is one higher than the binary knows exits non-zero with a message naming both versions, and leaves the store file, its WAL and the `runs` table unchanged.
- [ ] AC6: A second `verbatim ingest` launched while the first holds `LOCK` exits 0 in under 50 ms over 10 consecutive runs and adds no row to any table.
- [ ] AC7: Every line of a fixture transcript, including the eleven state record types that get no turn row, reads back from the blob byte-identical to the source file.

## Flagged assumptions

- The 64 KB block size is taken from `DESIGN-BRIEF.md:73` unmeasured against the corpus's real turn-size distribution (p50 726 bytes, p90 4,860) - Likely; if wrong: the median session is 2-3 blocks and per-block framing overhead is paid on mostly-small turns, which is the 11.2% penalty D-08 measured, and a different block size would move it.
- The eleven undocumented record types are stable enough not to break the turn classification in D-03 - Unclear; only Anthropic can confirm. If wrong: a new record type carrying `uuid` and `timestamp` silently becomes a turn, or a type that should be one is skipped. Mitigated by D-13: the bytes are always in the blob and `reindex` can reclassify.
- `~/.claude` is a symlink on this machine (`/home/john/.claude` -> `/claude/.claude` -> `/data/claude/.claude`), so the "canonicalize config roots or ingest twice" hazard at `DESIGN-BRIEF.md:406` is live from day one - Confident on the fact, Unclear on whether phase 1's single-file interface (D-18) must canonicalize its argument. If wrong: the same transcript is ingested under two paths and gets two archive rows.
