# Phase 4: One-Command Installer - Context

Gathered: 2026-10-13
Feeds: /cad-plan 4

## Scope boundary

In: `install.sh` at the repo root, with the shape of Baley's: given an `https://` source, it downloads `<source>/<os>-<arch>/manifest` and the binary, checks the SHA-256 in `verify_download` before placing anything, stores the binary in a folder per version, points the stable path `~/.local/bin/terminus` at it with a symbolic link, and ends by running `~/.local/bin/terminus install`. `terminus install` changes so it no longer copies itself over the stable path: it stores itself as a version and points the link at it, which is also how a local build is installed. Uninstall removes the link and leaves the versions. The tests run the script against a local HTTPS server. The docs that describe a copy at the stable path are brought in line, and `PROJECT.md`'s stale network constraint is corrected.
Out: signing and the signature check (Baley's release design #14, a later cycle), updates, pruning old versions, publishing any release, the README (phase 5), changing the workspace version from 0.1.1, and qualifying on macOS.
Deferred: None.
Plan shape: multiple plans, same phase. Suggested order: the install and uninstall change, then `install.sh` with its HTTPS test harness, then the docs.

## Durable decisions

- D-01 (Layout): `~/.local/bin/terminus` becomes a symbolic link to `~/.local/lib/crenshawdev/terminus/versions/<version>/terminus`, as Baley links `~/.local/bin/baley` into `~/.local/lib/crenshawdev/baley/versions`. The owner chose Baley's vendor folder over `~/.local/lib/terminus/versions` because Baley sets the style for the suite, though Terminus uses no vendor folder anywhere else. The versions folder sits under HOME and outside the data directory, because the data directory moves with `TERMINUS_DATA_DIR` and `terminus data move`, and `uninstall --purge` deletes it, which would delete the file every hook runs. `install.sh` stages the version, then moves a temporary link over the stable path with `mv -f`, after checking the stable path is not a folder. Claude Code uses the same layout on this machine (`~/.local/bin/claude` links to `~/.local/share/claude/versions/2.1.296`, measured 2026-10-13). Evidence: `/code/baley/install.sh:73-90,192-199`, `/code/baley/crates/baley/src/update/installation.rs:4-5,104`, `/code/baley/docs/adr/0027-vendor-folders-and-plain-keys.md`, `crates/terminus-core/src/store/open.rs:855-868`, `crates/terminus/src/cmd/data.rs:1`.
- D-02 (`terminus install` stores itself as a version): When the stable path is a link into the versions folder and `current_exe()` is that link's target, install leaves the binary alone. Run from anywhere else, such as `target/release/terminus`, install puts its own binary in the versions folder under its version and points the link at it. A local build is therefore `cargo build --release && target/release/terminus install`, with no manifest and nothing published, and it lands in the same layout `install.sh` makes. This settles what phase 2 D-08 left open and replaces `place()`'s copy over the stable path. Measured 2026-10-13: with a debug build in `versions/0.1.1/` behind a link, `<stable> install` left the stable path a regular 23,610,400-byte file and the link gone, because `place()` copies `current_exe()` (the link's target on Linux) to a temporary file and renames it over the link. The alternatives were Baley's (install never places the binary and a local build is linked by hand, which reverses the brief's binary layout) and an `install.sh` that also takes a `file://` folder. Evidence: `crates/terminus/src/cmd/install/binary.rs:15-18,158-201`, `crates/terminus/src/cmd/install/mod.rs:121`, `.planning/phases/2/CONTEXT.md` (D-08), `DESIGN-BRIEF.md:388,407`, `crates/terminus/tests/install.rs:345-372,1193-1235`, `/code/baley/crates/baley/src/install/plan.rs:317-326`.

## Decisions

- D-03 (Same version, different bytes): When a version folder already holds a binary with different bytes, the new binary is renamed over it, in both `install.sh` and `terminus install`. A running process keeps the old inode, and new hook runs use the new file. Every build reports 0.1.1 today, so without this every rebuild would be refused. Baley refuses with "staging conflict"; the owner chose replacing over that and over one folder per build (`0.1.1-<sha8>`). Same bytes are left alone. Evidence: `/code/baley/install.sh:174-190`, `Cargo.toml:6`, `crates/terminus/src/main.rs:91`.
- D-04 (Old versions): Old version folders are never deleted, and nothing prunes them in this phase, so a running session's MCP server and its hook's detached ingest keep their file. Measured on Linux 2026-10-13: a process started through a link to `v/1/sleep` kept `/proc/<pid>/exe` at `v/1/sleep` after the link moved to `v/2`. The MCP server starts no process, and the hook's detached ingest spawns `current_exe()`, which under the link is the version file. Evidence: `crates/terminus/src/cmd/spawn.rs:66-88,116-118`, `crates/terminus/src/cmd/hook.rs:200`, `crates/terminus/src/cmd/install/mod.rs:330-335`, `/code/baley/docs/adr/0038-installer-and-opt-in-updates.md:48`.
- D-05 (Marker through a link): The D-07 foreign-binary check needs no Rust change for a link. `occupant()` opens with `File::open`, which follows the link: a link to a marked binary is `Ours`, a link to an unmarked one is `Foreign`, and a dangling link is `Vacant`. Doctor's `binary` check and uninstall's `unplace` inherit this. Evidence: `crates/terminus/src/cmd/install/binary.rs:113-131`, `crates/terminus/src/cmd/doctor.rs:269-306`, `crates/terminus/src/cmd/uninstall.rs:347-372`.
- D-06 (Script shape): `install.sh` is Baley's script with `baley` swapped for `terminus`. It is POSIX `sh` with `set -eu`, takes one argument that must be `https://` with trailing slashes stripped, maps `uname -s` Linux and Darwin to `linux` and `macos` and `uname -m` x86_64 and aarch64 or arm64 to `x86_64` and `aarch64`, and refuses anything else. It fetches with `curl -q --proto '=https' --tlsv1.2 -fsSL`. The manifest is exactly `version X.Y.Z\nsha256 <64 lowercase hex>\n`. `verify_download` compares a `sha256sum` digest, falling back to `shasum -a 256`, before anything is staged. Staging goes through a temporary file and `mv`, and the last line is `"$stable" install`. Evidence: `/code/baley/install.sh:58-71,92-171,212`, `/code/baley/docs/adr/0038-installer-and-opt-in-updates.md:50`, `.planning/REQUIREMENTS.md` (INST-12).
- D-07 (Ownership in the script): `install.sh` decides who owns the stable path by the marker, as `terminus install` does. A regular file or a link carrying the marker is Terminus's and is replaced by the link; anything else is refused with a non-zero exit. Baley refuses every regular file, which would refuse the install on this machine: `~/.local/bin/terminus` is a regular 8,662,008-byte file, version 0.1.1, carrying `terminus-stable-binary:8f3d1a6c-...` once at byte 867942 (measured 2026-10-13). Under `sh`, GNU grep 3.12 `LC_ALL=C grep -q -F <marker>` finds it; the interactive shell's `grep` is a ugrep function that does not, so measure under `sh` only. The script holds its own copy of the marker, and a test ties that copy to `binary::MARKER`. Evidence: `crates/terminus/src/cmd/install/binary.rs:52-62,109-131`, `/code/baley/install.sh:73-90`, v0.1.0 phase 4 D-07.
- D-08 (Exit status): When `"$stable" install` exits non-zero, `install.sh` exits non-zero, and the receipt above it is the message. With no `claude` on `PATH`, the installed binary exits 1 with "install incomplete: the mcp server is not registered" (measured 2026-10-13), as phase 3 D-05 designed. Evidence: `crates/terminus/src/cmd/install/mod.rs:210-218`, `.planning/phases/3/CONTEXT.md` (D-05).
- D-09 (`TERMINUS_BIN_DIR`): `install.sh` refuses to run when `TERMINUS_BIN_DIR` is set. That variable exists for tests and `terminus install` honors it, so the script would otherwise link `~/.local/bin/terminus` while the install it runs pointed the hooks and the MCP entry somewhere else. Evidence: `crates/terminus/src/cmd/install/binary.rs:43-50,77-88`, `/code/baley/install.sh:96-117`.
- D-10 (Testing): `install.sh` is tested from Rust integration tests in `crates/terminus/tests/`, each with a temporary HOME, real `sh`, `curl`, `sha256sum` and `mktemp`, and phase 3's fake `claude`. The artifacts are served by `openssl s_server -WWW` with a throwaway certificate that `CURL_CA_BUNDLE` names, so the script stays https-only. Checked 2026-10-13: curl with the script's flags fetched a file from that server with `CURL_CA_BUNDLE` set. `PATH` puts the fake `claude`'s folder first and then the system folders, because the `PATH` holding only the fake `claude` that `tests/install.rs` uses today cannot run coreutils; the real `claude` is in `~/.local/bin`, so it stays unreachable. The `shasum` fallback is reached by leaving `sha256sum` off a shaped `PATH`, and the system refusal by a fake `uname`. Static checking is `sh -n` only: shellcheck, dash, ksh, mksh, posh, yash and busybox are not installed, and `/bin/sh` is bash (measured 2026-10-13). Evidence: `crates/terminus/tests/install.rs:1-12,101-165`, v0.1.0 phase 4 SUMMARY (shellcheck).
- D-11 (Uninstall): Uninstall removes the stable-path link and leaves the versions folder, printing its path as it prints the data directory. `unplace` already calls `remove_file`, which removes only the link. INST-07 limits uninstall to what `terminus install` put in. Evidence: `crates/terminus/src/cmd/uninstall.rs:1-9,347-372`.
- D-12 (Doctor): Doctor's binary check stays marker plus version and is not taught about the versions folder. Through the link, `occupant` and `version_at` report the active version, and the fix command's `current_exe()` becomes the version file's path on Linux. Evidence: `crates/terminus/src/cmd/doctor.rs:203-230,269-346`.
- D-13 (Network statement): PRIV-05's "opens no network connection" covers the Terminus binary. `install.sh`'s `curl` download is the one network use, and the docs say so. `PROJECT.md:104` still reads "no network connections except the configured model provider", stale since phase 1, and is corrected in this phase. Evidence: `.planning/REQUIREMENTS.md` (PRIV-05, DOC-01), `DESIGN-BRIEF.md:315,321,398`, `.planning/PROJECT.md:104`.
- D-14 (Docs): `DESIGN-BRIEF.md`'s binary layout ("That copy is canonical" at `:388`, "re-copies it to the stable path" at `:407`) describes the link and the versions folder, `PROJECT.md:104` is corrected per D-13, and `CHANGELOG.md` `[Unreleased]` records `install.sh` and the link. Evidence: the files named.

## Acceptance criteria

- [ ] AC1: `sh install.sh <source>` exits non-zero and leaves the stable path and the versions folder untouched in three cases: the manifest's SHA-256 doesn't match the binary, `uname` reports a system or architecture other than Linux or Darwin on x86_64 or aarch64, or the source is not `https://`.
- [ ] AC2: After `install.sh` installs version A and then version B, `~/.local/bin/terminus` is a link to `~/.local/lib/crenshawdev/terminus/versions/B/terminus`, A's file is still on disk unchanged, and a process started through the link before the second install is still running from A's file.
- [ ] AC3: One `sh install.sh <source>` run with a fake `claude` that succeeds ends with the hooks merged and `claude mcp add-json` logged, and exits 0. With no `claude` on `PATH`, it exits non-zero.
- [ ] AC4: A stable path holding a file without the Terminus marker is refused by both `install.sh` and `terminus install`: non-zero exit, file unchanged. A plain file that carries the marker, like an install from before this phase, is replaced by the link.
- [ ] AC5: `target/release/terminus install` stores the build at `versions/<its version>/terminus` and points the link at it. After a rebuild at the same version, it replaces that file. `~/.local/bin/terminus install` leaves the link and the version file unchanged.
- [ ] AC6: `terminus uninstall` removes the link, leaves the versions folder, and prints its path. `sh -n install.sh` passes, and `cargo test --workspace --all-features` passes.
- [ ] AC7: `DESIGN-BRIEF.md` describes the link and the versions folder, not a copy at the stable path. `PROJECT.md` no longer says "except the configured model provider". `CHANGELOG.md` `[Unreleased]` records `install.sh`.

## Flagged assumptions

- On macOS, `std::env::current_exe()` for a process started through a symbolic link may return the link rather than its target; only Linux was measured. - Unclear; if wrong: D-02's "run from the installed version" test fails on a Mac, and every rerun of `~/.local/bin/terminus install` stores the same bytes again, which D-03 makes harmless but not silent.
- macOS's BSD `grep -q -F` may not find the ASCII marker in a binary file without `-a`. - Unclear; if wrong: `install.sh` on a Mac refuses Terminus's own plain-file install, unless the planner picks a marker check that does not depend on grep.
- Baley's script uses `mktemp`, `readlink`, `mv -f` of a link over a link and `shasum -a 256` in ways that work under macOS's BSD tools. Baley's T17 qualified Linux only. - Likely; if wrong: the script fails on a Mac, which criterion 6 already leaves unverified.
- An unsigned development binary downloaded with curl runs on macOS aarch64 with no extra step (ad-hoc linker signature, quarantine attribute). - Unclear; if wrong: a Mac install needs a signing or quarantine step, which belongs with Baley's release design (#14).
- Every build reports 0.1.1, while `CHANGELOG.md` numbers unreleased work 0.0.x. Version folders are named after whatever the build reports, and changing the workspace version is not this phase's work. - Confident; if wrong: nothing changes for this phase.
- A link the owner made by hand to a marked binary outside the versions folder, such as `target/release/terminus`, passes doctor as `Ours`, and it disappears with `cargo clean`. Baley's doctor checks that the link points into the versions folder (`judge_active`); D-12 does not. - Likely that nobody does this once D-02 lands; if wrong: hooks break silently after `cargo clean`.
- The test server's port and how a test waits for it to listen are the planner's call. - Confident; if wrong: a flaky test, nothing else.
