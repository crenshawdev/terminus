Each claim the README makes under Trust and Current state, with the file or issue that backs it.

### Trust

- Terminus collects nothing about you, sends no telemetry, and sends data only to services you configure. Backed by `crates/terminus-core/tests/no_network.rs` (`no_source_file_names_a_socket`), and by `crates/terminus-core/src/config.rs`, where loading refuses a leftover `[provider]` table (`if file.provider.is_some()`).
- Linux and macOS meet the platform standard, Windows fails it and is not supported, and the criteria and reasoning are in TRUST.md. Backed by `TRUST.md` ("Linux and macOS meet all three. Windows fails all three.") and `crates/terminus-core/src/lib.rs` (`compile_error!("Terminus supports Linux and macOS only.")`).
- A supported platform that stops meeting the standard loses support. Backed by `TRUST.md` ("A supported platform that stops meeting them loses support.").
- The install line fetches `install.sh` from `raw.githubusercontent.com`. Backed by the line itself in the README's Installing and updating section, which `.github/workflows/release-check.yml` runs in its step "Install with the one-line command".
- `install.sh` uses `curl` to fetch the manifest, its signature and the binary from the GitHub releases of crenshawdev/terminus, or from the `https://` source you pass it. Backed by `install.sh`: `source=https://github.com/crenshawdev/terminus/releases/latest/download`, `case $1 in https://*) source=$1`, and its three `curl -q --proto '=https'` calls.
- The `SessionStart` hook may hand Claude Code a brief, and the `UserPromptSubmit` hook may hand it earlier turns. Backed by `crates/terminus/src/cmd/hook.rs` (`fn inject`, which sends `SessionStart` to `inject::brief::session_start` and `UserPromptSubmit` to `inject::prompt::user_prompt_submit`).
- `recall_search`, `recall_context` and `recall_get` return archived turns when Claude calls them. Backed by `crates/terminus/src/cmd/mcp/tools.rs` (`RECALL_SEARCH`, `RECALL_CONTEXT`, `RECALL_GET`).
- Claude Code sends that text to its model with the rest of the session. Backed by `crates/terminus-core/src/observe/egress.rs`, whose module comment names the brief, the per-prompt injection and the three tools' results as text on its way into the model's context through a hook or the MCP server.
- `[privacy] redact_recall = true` filters that text on its way into Claude Code. Backed by `crates/terminus-core/src/observe/egress.rs` (`for_model_context`, `Redaction`) and `crates/terminus-core/src/config.rs` (`Config::redact_recall`).
- `[injection] brief_chars` and `prompt_chars` cap how much each hook hands over. Backed by `crates/terminus-core/src/config.rs` (`DEFAULT_BRIEF_CHARS`, `DEFAULT_PROMPT_CHARS`), `crates/terminus-core/src/inject/brief.rs` (`budget.min(MAX_BRIEF_CHARS)`) and `crates/terminus-core/src/inject/prompt.rs` (`config.prompt_chars().min(MAX_PROMPT_CHARS)`).
- Every release is signed on the maintainer's machine, never in CI. Backed by `scripts/sign-release.sh` ("Sign and publish a draft release of Terminus, on the owner's machine") and `.github/workflows/release.yml` ("the owner signs and publishes from his own machine, so no key is here").
- The release workflow only builds the binaries and drafts the release, and no workflow holds a key. Backed by `.github/workflows/release.yml` (`permissions: contents: read`, with only the `draft` job given `contents: write`, using the job's own token) and `.github/workflows/release-check.yml`. Neither workflow names a secret.
- `install.sh` checks the manifest's signature against the key pinned in the script before it reads the manifest or downloads the binary. Backed by `install.sh`: `release_key='ssh-ed25519 ...'`, and `ssh-keygen -Y verify -f "$scratch/allowed_signers" -I crenshawdev-release -n terminus-release`, which runs before the binary's `curl` and before the manifest's lines are read.
- `install.sh` then checks the binary against the manifest's SHA-256, and installs nothing that fails either check. Backed by `install.sh`: `verify_download` ("download SHA-256 is $actual, but the manifest names $sha256"), and `fail`, which exits 1 before anything is staged.
- The Terminus binary opens no network connection, and a test fails if any source file in either crate names a socket type. Backed by `crates/terminus-core/tests/no_network.rs` (`no_source_file_names_a_socket`, over `BANNED`: `std::net`, `TcpStream`, `TcpListener`, `UdpSocket`).
- How a release is built, signed and checked, and how to check one by hand, is in `docs/release.md`. Backed by `docs/release.md`.

### Current state

- The tests do not run in CI. The release workflow builds and drafts releases, and no workflow runs the test suite. Backed by [#47](https://github.com/crenshawdev/terminus/issues/47), and by `.github/workflows/`, which holds only `release.yml` and `release-check.yml`, neither running `cargo test`.
- `[privacy] redact_recall` misses a bare OpenAI-style `sk-` token in plain prose, because none of its rules recognizes that shape. Backed by [#5](https://github.com/crenshawdev/terminus/issues/5) and the shape rules in `crates/terminus-core/src/observe/egress.rs`.
- With `[privacy] redact_recall` on, `terminus show` runs each archived line through a lossy UTF-8 round trip before it filters it. Backed by [#1](https://github.com/crenshawdev/terminus/issues/1) and `crates/terminus-core/src/recall/get.rs` (`String::from_utf8_lossy(&bytes)` in the `redaction.is_on()` arm).
- What the `recall_search`, `recall_context` and `recall_get` tools return is not documented, and the tool table in `DESIGN-BRIEF.md` is out of date. Backed by [#26](https://github.com/crenshawdev/terminus/issues/26) and the tool table in `DESIGN-BRIEF.md`.
