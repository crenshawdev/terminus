- The response schema travels in the system message, not in `response_format`. PLAN-2's `observe::provider::complete` sends D-09's `{"type":"json_schema","strict":true}` for every caller from a private constant, and `provider.rs` is outside this plan's `files:` lease. The Verify only asks that a schema-shaped answer be parsed and anchored, which the prompt-borne schema meets. Worth noting for AC4's remote half: a strict OpenAI-compatible endpoint may reject a `json_schema` response_format that carries no `json_schema` object, which would need a one-line change in `provider.rs`.
- The `observations regenerate` JSON `data` object gained NO new fields. `Regenerated` carries typed `judged` and `unasked` counts, but they are reported through the existing `notes` array (a `re-judged N of M selected session(s)` line, and a `left unasked` line when the budget stops the run) and on stderr without `--json`. Adding `judged`/`unasked` as document fields would break `crates/verbatim/tests/cli.rs`'s exact key-set assertion, and that file is outside this plan's `files:` lease; the Verify asks only that the run "reports that it stopped", which `notes` carries. Promote them to fields with a lease that includes `cli.rs`.
- `cost::JUDGED_PER_PASS = 1` is a fifth bound the plan did not name. Without it a pass could make up to 100 sequential provider calls at a 120 s network timeout each, which is the long-lived detached process `.planning/PROJECT.md` rules out as a design invariant; the hook spawn is the scheduler and `observations regenerate` is the bulk path. Raise it if a task states a second value.
- Declined a `Store`-level accessor pair for the daily-spend row. `Store::meta_int`/`set_meta_int` exist but take `&self` on `Store`, and every `observe` entry point holds a bare `&Connection`; D-12 admits "an equivalent pair over the same table", so the spend reads and writes `meta` directly from `cost.rs`. Promote it if a second caller outside `observe` ever needs the day's spend.
- A reservation abandoned by a killed process is taken by the next pass once its 900s lease lapses, and where the dead run was an `observations regenerate` over an already-judged row, taking it buys a second answer for a session that had one. That is the price of the row being repaired at all - the alternative is a status column stuck on `judging` forever - and it is bounded by `cost::JUDGED_PER_PASS`. Carrying the replaced status inside the token would let the stealer restore it for free instead; that is a token-format change and was not needed to close the finding.
