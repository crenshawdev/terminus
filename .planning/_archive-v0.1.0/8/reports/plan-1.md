Open items:
- The `--test retention` and `--test pass` Verify commands need `--features testkit`: without it those files are `#![cfg(feature = "testkit")]`-gated and cargo reports "0 passed" as a pass. Every count above is from a `--features testkit` run.
- Task 2's Action pictures a single `cutoff: &str`, which cannot serve the per-project `age_days` the same plan's `## Must be true when done` requires. The parameter is the evaluation INSTANT instead, and each policy's cutoff is computed from it in SQL with the same `strftime` shape - one clock reading for the whole evaluation, which is the property the Action was after. The instant travels back out on `Selection.evaluated_at`, so PLAN-2's dry-run reports what it measured from.
- `retention::evaluate` passes over sessions in excluded projects and counts them (`Selection.excluded`, reported as a `runs.error` line), following `observe::observe_new`'s precedent and ING-08. Not asked for by the Verify; taken because the alternative under the `destructive` surface is deleting bytes a user said never to read, and the count keeps the choice from being silent rather than letting a policy that reclaims nothing read as broken.
- `Applied::lines()` summarizes by count rather than naming every session key: `runs.error` is read by a human and a hundred keys is not a report. The keys are still on `Applied.evicted`/`.deleted` for a caller that wants them, and PLAN-2's `--dry-run` is where the id list belongs.
- `transcript_is_gone` treats only `NotFound` as gone; a permission or unreadable-mount error leaves the session alone. Declined the fuller shape of reporting those as notes - nothing in the plan asks and a store on a briefly unreadable mount would then write a note per session per pass.
