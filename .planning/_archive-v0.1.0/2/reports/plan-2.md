Open items:
- `record_run`'s single-file (`RunRow::PerFile`) path in `crates/verbatim-core/src/ingest/mod.rs` still does not name `files_committed` / `files_failed`, so a single-file ingest reports `0 committed` in `verbatim status`. Carried in from PLAN-1's risk review; no task here touches that function and none made it more fixable in passing.
- `crates/verbatim-core/tests/lineage.rs` is now `#![cfg(feature = "testkit")]`, so like every other testkit-gated test file it is silently skipped by a bare `cargo test -p verbatim-core` (phase 1 open item). `cargo test --workspace` runs it.
- `verbatim status` now loads `Config`, so a `verbatim.toml` that does not parse fails `status` (exit 1) where it previously succeeded. That is the config loader's deliberate refusal (`Error::ConfigParse`), applied to a read command for the first time.
- `project::Resolver` spawns `git` at most once per distinct `cwd` per pass; the first real-corpus pass will spawn it for the 30 surviving directories, inside the ingest lock. If that ever matters, the memo could be persisted, which no phase-2 requirement asks for.
- AC3's worktree half and every git-backed project test skip themselves when `git` is absent from `PATH`, so a CI image without git degrades to the non-git cases rather than failing.
