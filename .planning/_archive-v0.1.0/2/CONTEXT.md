# Phase 2: Ingest At Scale - Context

Gathered: 2026-08-12
Feeds: /cad-plan 2

## Scope boundary

In: The no-arg tree walk over canonicalized transcript roots, filename-pattern discovery to unbounded depth including nested subagent sidecars, session lineage (`continues_from`, `parent_session_key`), project identity from `cwd` with worktree mapping, project-level exclusion enforced before any open, the `compact_boundary` record and its metadata, per-file failure isolation and recovery at the top of every run, the `runs` table as a per-pass record including failures, `verbatim status`, and verbatim's own config loader (roots and exclusions).
Out: Rust-side text expansion, entity extraction, search and the MCP tools (phase 3) - phase 2 fills `turns` and `turns_fts` through the phase 1 derive seam but does not change what that seam extracts. Hooks, install, backfill and bounded-parallelism fan-out (phase 4) - the pass stays single-threaded here. Interpreting `compactMetadata` into a dropped-turn set (phase 5, INJ-05). Retention, eviction and deletion (phase 8).
Deferred: ING-07 capture mode (`full` / `lean` / `minimal`) - elision at ingest contradicts D-13 (the blob holds the transcript bytes verbatim) and would break the phase 1 invariant `the_blob_reproduces_the_transcript_byte_for_byte` in the phase that first ingests the real corpus. Belongs with phase 8, where elision is already the subject. ROADMAP.md still lists ING-07 under phase 2 and needs a `/cad-phase` edit to move it.
Plan shape: multiple plans, same phase

## Durable decisions

- D-01 (Session linking): `continues_from` rejects a `session_id` equal to the file's own, so a session never links to itself. Evidence: `crates/verbatim-core/src/ingest/mod.rs:274-282` takes the first `foreign_session_id` with no comparison; measured over all 1,253 top-level transcripts - 433 carry a `session_id` field, of which 253 carry only their own id, 169 only another session's, 11 both. Phase 1's D-11 figure (187/1,221 = 15.3%) did not separate these; the real continuation rate is 180/1,253 = 14.4%. If wrong: one in five archived sessions claims to continue from itself, and every phase 3/5 thread walk either cycles or special-cases the self-edge at each read site.
- D-02 (Session linking): Continuation is a fan-out, not a chain - one predecessor may name several successors, so thread reconstruction is a tree walk. Evidence: measured - session `ebd78c2b` is named as predecessor by four separate later transcripts in the same project (172-turn predecessor, successors of 175/168/295/294 turns); 11 files carry two distinct `session_id` values. If wrong: a single-successor assumption shows one fork and silently hides the others, and INJ-01's resume brief points at the wrong "last session".
- D-03 (Session linking): A sidecar's parent is derived from its path (`<project>/<sessionId>/subagents/...`), never from its records, and lands in `session_meta.parent_session_key`. Evidence: `parent_session_key` exists and is left null by phase 1 (`crates/verbatim-core/src/ingest/mod.rs`, `write_session_meta`); phase 1 D-01; measured - all 822 files under a `subagents/` path sit in a directory named for an existing top-level transcript's session id (822/822), and 818/818 `agent-*.jsonl` files report that same id as their own `sessionId`, so the record-level id distinguishes nothing. If wrong: sidecars link to themselves or to whichever session shares the id, and phase 3 has no column to filter subagent turns out of a brief.
- D-04 (Session linking): The `agent-*.meta.json` beside each sidecar is read and its bytes stored opaquely in a `session_meta` column, not parsed into typed columns. Evidence: 816 such files carry `agentType`, `description`, `toolUseId`, `spawnDepth`, `model`; D-12 (phase 1) excludes them from transcript discovery by filename; `crates/verbatim-core/src/store/schema.rs` has no column for any of it. Keeps D-13 intact (the blob stays transcript bytes only) while letting phase 3 extract `description` for ranking without a reingest, and avoids betting typed columns on an undocumented format. If wrong: a schema column holds bytes nothing ever reads.
- D-05 (Project identity): Project resolution runs git only when the `cwd` directory still exists, and degrades to the canonical `cwd` string otherwise. Evidence: measured over the 63 distinct first-`cwd` values in the corpus - 33 no longer exist on disk (52%), 17 of the surviving 30 are git repositories, 13 are not, so `git rev-parse --show-toplevel` answers for 17 of 63 distinct paths (27%). If wrong: half the archive gets a null project and drops out of every project-scoped search and resume brief, or ingest shells out to git thousands of times for answers it cannot get.
- D-06 (Project identity): Worktree-to-parent mapping uses a path-shaped rule (a `cwd` of the form `<repo>/.claude/worktrees/<x>` maps to `<repo>`) rather than `git rev-parse --git-common-dir`, and the resolved mapping is persisted so a later directory deletion does not un-key already-archived sessions. Evidence: measured - every worktree `cwd` in the corpus has exactly that nested form, and all 13 are deleted, so git returns nothing for any of them; the encoded directory names preserve the relationship literally (`-data-code-cadence--claude-worktrees-agent-a33a...` beside `-data-code-cadence`). AC3 therefore cannot be demonstrated against live corpus data and needs a constructed repo+worktree fixture. If wrong: six `cadence`, six `hindsight` and six `assistant` worktrees each become their own project, splitting one project's history across seven keys - the identity fragmentation PROJECT.md cites claude-mem for.
- D-07 (Project identity): The encoded project directory name is never decoded into a path. Evidence: measured - applying `[^A-Za-z0-9] -> '-'` to each transcript's first `cwd` reproduces its containing directory name for 1,252 of 1,252 files carrying a `cwd`, so the encoding is exact and provably lossy: `/data/code/jcrenshaw.dev` (7,635 records) encodes to `-data-code-jcrenshaw-dev`, indistinguishable from `/data/code/jcrenshaw-dev`. If wrong: two unrelated projects merge under one key, or one splits, and the merge is unrecoverable without a reindex from `cwd`.
- D-08 (Compaction): The `compact_boundary` record's `compactMetadata` is stored verbatim and no dropped-turn set is computed in this phase; the complement is derived at query time in phase 5 (INJ-05). Evidence: measured over all 300,556 records - exactly one `compact_boundary` exists, in `-data-projects-hephaestus/095cee31-*.jsonl`, and its `preservedMessages.uuids` (6) is a subset of `allUuids` (8) against `preTokens` 45,500 / `cumulativeDroppedTokens` 38,064, so the uuid lists describe the preserved segment and cannot enumerate the ~38k dropped tokens. `DESIGN-BRIEF.md:140` states the opposite ("exactly which turns fell out") and is the claim this measurement contradicts. Storing verbatim makes a wrong reading fixable without a reingest. If wrong: nothing, by construction - the bytes and the metadata are both retained.
- D-09 (Exclusion): The pre-read exclusion test compares an encoded exclusion prefix against the encoded directory name, matched on encoded path-segment boundaries so `-data-projects-cadence` does not match `-data-projects-cadence-research`. Evidence: AC5 requires no read of an excluded file, `cwd` is only available from a parsed record (`crates/verbatim-core/src/parse/record.rs`), and no directory-to-project table exists (`crates/verbatim-core/src/store/schema.rs`); D-07's encoding is exact, so encoding both sides is the only zero-open test available. Residual known imprecision: `/data/code/jcrenshaw.dev` and `/data/code/jcrenshaw-dev` remain the same test. If wrong: a user silently loses projects they never excluded, or an excluded project is read. [corrected by plan-2 gate: the two clauses are not jointly satisfiable - a child and a hyphenated sibling encode to one name - so an encoded name that extends an exclusion is now resolved against the filesystem, and an unresolvable case excludes rather than reads]
- D-10 (Runs): One `runs` row per pass, not per file. Evidence: `crates/verbatim-core/src/ingest/mod.rs` `record_run` inserts a literal `1` for `files_seen` and is called inside the per-file transaction; reused unchanged, a tree walk would write ~2,071 rows per pass and ING-09's "the last ingest run" would name one file rather than the pass. If wrong: `verbatim status` reports the last file touched instead of the last pass, and `runs` grows by thousands of rows per hook-triggered ingest.
- D-11 (Recovery): Per-file transactions and per-file watermarks are what make a killed pass converge; the pass itself is not one transaction. Evidence: `crates/verbatim-core/src/ingest/mod.rs` module docs reject holding a write transaction across a whole pass (it stops MCP readers, `DESIGN-BRIEF.md:83`), and the phase 1 crash harness (`crates/verbatim/tests/crash.rs`, 23 SIGKILLs) proves atomicity at exactly that granularity; measured file sizes p50 290 KB, p90 1.03 MB, p99 3.1 MB, max 10.1 MB bound the in-flight loss. If wrong: a mid-pass kill either loses every file already committed, or leaves a half-pass AC6's convergence claim cannot be stated about.
- D-12 (Recovery): A per-file failure is recorded and skipped, never fatal to the pass - phase 1's two hard-error paths become per-file skips. Evidence: `Existing::read` returns `Error::NotAStore` for a session archived without a `session_meta` row, and `read_tail` returns an IO error when a file is shorter than its watermark, both in `crates/verbatim-core/src/ingest/mod.rs`; under D-18's one-file CLI those correctly fail the command, under a tree walk either stops the remaining 2,000+ files. `crates/verbatim-core/src/reindex.rs` `Rebuilt::failed` already established the pattern after gate fix `3e5d9ff`. If wrong: one damaged session wedges every future ingest of every other transcript - the identical failure that gate fix closed for `reindex`.
- D-13 (Recovery): A transcript shorter than its stored watermark is skipped with its error recorded, never re-ingested from offset 0, and the session is flagged so `verbatim verify` reports the divergence. Evidence: the append-only property is an observation over one 25-day corpus (`DESIGN-BRIEF.md:139`), not a documented guarantee; D-16 (phase 1) scopes `verify` to checksums, so the flag is a new signal path this phase adds. Never destroys archived bytes; a genuinely reset transcript stays stale until a human looks. If wrong: a legitimately reset transcript is permanently stale in the archive.
- D-14 (Status): A failed pass writes its `runs` row in a second transaction after the rollback. Evidence: `crates/verbatim-core/src/ingest/mod.rs` `record_run` is called inside the pass transaction and its doc comment states a failed pass needs a second transaction after rollback and is phase 2's (ING-03, ING-09); `runs.error` exists and is never written; no `status` subcommand exists (`crates/verbatim/src/cmd/mod.rs` ships three). If wrong: AC7 is unsatisfiable - a failed pass leaves no row, and with no log file by design the failure is invisible.
- D-15 (Config): Verbatim reads its own config path and never touches `~/.config/verbatim/config.toml`, which the legacy verbatim wrote (184 bytes, `base_dir = "/data/verbatim"`) and whose data import PROJECT.md defers. Transcript roots are a list in that config; `CLAUDE_CONFIG_DIR` is read as a single directory override. Evidence: no config loader and no TOML dependency exists anywhere in the workspace; `DESIGN-BRIEF.md:406` says roots accept a list but the separator convention is Claude Code's and the variable is unset here, so multi-root is supported without guessing anyone else's separator. If wrong: the new store silently adopts the legacy `base_dir` and writes into the deferred legacy data directory.

## Decisions

- D-16 (Discovery): Discovery filters by filename pattern under a canonicalized root and recurses to unbounded depth, accepting `<uuid>.jsonl` at project depth and `agent-*.jsonl` at any deeper level, never inferring transcript-ness from record shape. Evidence: phase 1 D-12; `crates/verbatim-core/src/parse/record.rs`; `crates/verbatim-core/src/testkit.rs` (`NON_TRANSCRIPT_FIXTURE`). Measured - 2,075 `.jsonl` files = 1,253 top-level `<uuid>.jsonl` (1,253/1,253 match the uuid pattern), 818 `agent-*.jsonl`, 4 `journal.jsonl`; sidecars sit at depth 4 (781) *and* depth 6 (41, under `subagents/workflows/wf_*/`); 232 `subagents/` directories, not the roadmap's 214; also present and correctly excluded by a filename filter are 816 `agent-*.meta.json`, 4 `workflows/wf_*.json`, and 131 `tool-results/` directories of `.txt`/`.md`. If wrong: a depth-limited walk silently drops the 41 deep files, and no test on the synthetic fixture set catches it.
- D-17 (Discovery): The pass canonicalizes the transcript roots once and joins walked entries onto them, rather than calling `canonicalize()` per file. Evidence: `crates/verbatim-core/src/ingest/mod.rs:60-66` canonicalizes per invocation today, correct for phase 1's one-file interface, and the session key is that canonical path string; measured - zero symlinks anywhere inside the tree, while the root itself is a two-hop symlink chain (`/home/john/.claude -> /claude/.claude -> /data/claude/.claude`), so root canonicalization alone yields identical keys. Closes the phase 1 flagged assumption. If wrong: a symlinked project directory appearing later produces a second `sessions` row and a second blob for a transcript already archived.
- D-18 (Discovery): The pass is sequential and single-threaded; rayon stays out of phase 2. Evidence: phase 1 D-17 and the workspace `Cargo.toml` (no rayon, walkdir or glob dependency today); ING-11's bounded-parallelism backfill is phase 4. Measured - a warm read of all 988 MB takes 0.051 s and `zstd -3` over the same bytes 1.20 s, so the pass cost is the ~255,000 `turns` + `turns_fts` inserts through the single SQLite writer, which cannot fan out. If wrong: phase 4's backfill retrofits parallelism into a walker built assuming one thread.
- D-19 (Session linking): `continues_from` may name a session absent from the store; the column holds the id with no foreign key and no ingest-order requirement. Evidence: `session_meta.continues_from` is a bare indexed `TEXT` in `crates/verbatim-core/src/store/schema.rs`; measured - of the 173 files naming a foreign session, 171 resolve to a transcript still on disk and 2 do not (predecessors aged out by `cleanupPeriodDays`); all 171 resolved pairs sit in the same project directory with the predecessor's last timestamp before the successor's first and zero shared turn uuids. If wrong: ingesting a successor before its predecessor drops the link or errors.
- D-20 (Project identity): A session's project comes from its first `cwd` record; a transcript whose `cwd` changes mid-session keeps the first. Evidence: `crates/verbatim-core/src/ingest/mod.rs` `write_session_meta` uses `find_map` with `coalesce(session_meta.cwd, excluded.cwd)`, so first-writer wins and a tail pass never revises it; measured - 19 of 1,253 top-level transcripts (1.5%) carry more than one distinct `cwd`, and 1 carries none at all. If wrong: 19 real sessions are filed under a directory most of the work did not happen in, and one session has a null project no read path expects.
- D-21 (Compaction): A compaction boundary is a `type: "system"` record with `subtype: "compact_boundary"`, which phase 1's D-03 already classifies as a turn, so ING-06 adds a derived boundary row rather than a new record class. Evidence: `crates/verbatim-core/src/parse/record.rs` (`TURN_TYPES` includes `system`; classification needs `uuid` + `timestamp`, both present on the real record, which also carries `logicalParentUuid` and the full `compactMetadata` block). If wrong: the boundary is filed as an ordinary system turn with no metadata row and phase 5 has no candidate pool.
- D-22 (Exclusion): Exclusion is decided at the project directory level before any file in it is opened, which also covers sidecars. Evidence: AC5 requires no read shown by an instrumented-open trace; `cwd` is only available from a parsed record and `read_tail` opens the file to get it (`crates/verbatim-core/src/ingest/mod.rs`); measured - all 822 sidecar files sit under `<project>/<sessionId>/subagents/`, so a directory-level skip covers them. If wrong: every excluded transcript is opened to discover it should not have been, failing AC5 by construction.
- D-23 (Exclusion): The read-path half of ING-08 stores no per-session flag; read paths re-apply the same predicate against `session_meta.project`. Evidence: `session_meta` has `project` and `cwd` and no `excluded` column (`crates/verbatim-core/src/store/schema.rs`); PROJECT.md's stated failure mode is claude-mem honoring exclusion on write and ignoring it on read. If wrong: sessions archived before a project was excluded stay searchable, since nothing on the ingest path retroactively hides them.
- D-24 (Recovery): Recovery at the top of a run is the existing `open_up_to_date` rebuild plus a bounded consistency sweep over `watermarks` versus committed blob bytes, exposed as one callable function - no new command and no stale-lock handling. Evidence: `crates/verbatim-core/src/reindex.rs::open_up_to_date` already runs on the ingest path; `crates/verbatim-core/src/ingest/lock.rs` uses an OS lock that dies with the process (phase 1 D-15/D-20), so there is no stale lock to recover from; the post-kill states are enumerable from the crash harness's own invariants. Scale consequence to plan around: a `DERIVED_SCHEMA` bump makes the next hook-spawned ingest rebuild all ~2,071 sessions from 988 MB of blobs inside the ingest lock before it walks anything. If wrong: ING-03's "recovery at the top of every run" is asserted by nothing that could fail.
- D-25 (Testing): No closed record-type set is asserted against the real corpus. Evidence: `crates/verbatim-core/tests/fixtures.rs::session_basic_carries_all_fifteen_record_types` asserts an exact 15-type set; measured by parsing every line of all 2,075 files - 0 unparseable lines and 0 non-object lines in 300,556 records, across 16 distinct top-level types including `pr-link` (391 records) and `frame-link` (7). The fixture assertion stays scoped to the fixture. If wrong: a phase 2 test fails on data that is correct.

## Acceptance criteria

- [ ] AC1: A pass over the real corpus tree ingests every `<uuid>.jsonl` and `agent-*.jsonl` beneath the root at any depth including those under `subagents/workflows/wf_*/`, ingests no `journal.jsonl`, `.meta.json` or `tool-results/` file, reports zero unparseable lines and zero panics, and its session count exceeds the top-level file count by the sidecar count.
- [ ] AC2: After that pass, the count of non-null `continues_from` values is non-zero, and the count of rows whose `continues_from` equals their own session id is zero.
- [ ] AC3: Two transcripts whose `cwd` values are a git repo and a worktree beneath its `.claude/worktrees/` resolve to one project key, and two transcripts whose `cwd` values are `/x/a.b` and `/x/a-b` resolve to two different project keys.
- [ ] AC4: Appending a `compact_boundary` record to an already-ingested transcript and rerunning ingest adds a boundary row carrying that record's `compactMetadata` verbatim, and every turn row and committed blob block from the earlier pass is byte-identical afterwards.
- [ ] AC5: With a project excluded, a pass over a tree containing it records zero opens of any file under that directory on the instrumented open counter and adds no row to any table, while a sibling directory sharing the excluded path's leading segments is ingested normally.
- [ ] AC6: Killing a pass at 10 or more randomized points and rerunning to completion yields the same blob checksums, turn rows and watermarks as one uninterrupted pass over the same tree.
- [ ] AC7: A tree containing one damaged transcript (short of its watermark, or archived with no `session_meta`) completes ingest of every other file in the tree, and `verbatim status` prints the run with that file's error alongside store sizes, counts and watermarks.

## Flagged assumptions

- Upstream semantics of `compactMetadata.preservedMessages.uuids` versus `allUuids` versus `preservedSegment` are unsettled - Unclear; one real example exists in 300,556 records and the design brief's reading of it conflicts with what that example's own token counts imply. D-08 contains the risk by storing the metadata verbatim, so phase 5 pays the cost of a wrong reading, not phase 2.
- Whether Claude Code ever truncates or rewrites an existing transcript in place - Unclear; only Anthropic can confirm. If wrong in the direction of "yes, routinely", D-13's skip-and-flag leaves those sessions permanently stale and the flag becomes a recurring `verify` complaint rather than an alarm.
- The `agent-*.meta.json` format (`agentType`, `description`, `toolUseId`, `spawnDepth`, `model`) is undocumented and may drift - Likely stable enough for D-04's opaque storage; if wrong, nothing breaks at ingest because the bytes are stored unparsed, and phase 3 discovers the drift when it tries to extract `description`.
- Coverage of `agent-*.meta.json` is 816 files against 818 sidecar transcripts - Confident on the count; the 2 sidecars with no meta file need a null-tolerant path.
- The phase 1 open item stands: the crash harness only ever kills a first pass into a fresh data directory, never an append/resume pass - Confident. AC6 walks a tree with already-ingested files, which is the first time that path is killed; the planner should keep the harness's negative test honest about which watermark property it asserts (`CAPTURE.md`, phase 1 SUMMARY deviation).
- ROADMAP.md still lists ING-07 under phase 2 after the deferral - Confident; needs a `/cad-phase` edit, which this workflow does not perform.
