Deviations:
- [deviation] Task 1 `Verify:` says the real-corpus transcript count lands "within a file or two" of `find <corpus> -name '*.jsonl' | wc -l` and the byte total "within a percent of `du -sb`". Observed against `/claude/.claude/projects` (the corpus reachable here; `/data/claude/.claude` does not exist from this worktree): `find` counts 3,119 and backfill counts 3,115 - off by four, and all four are the `journal.jsonl` files `discover.rs` D-16 documents as non-transcripts, so backfill's count is the correct one and `find` is the loose instrument. `du -sb` reports 1,514,024,180 against backfill's 1.4 GB, a 6.6% gap, because `du -sb` counts directory inodes and every non-transcript file in the tree; the sum of `.jsonl` file sizes is 1,413,907,546, which backfill matches exactly. Both yardsticks in the plan are wider than the thing they measure; no code changed on account of it.
- [deviation] Task 1 `Action:` says to calibrate the estimate as "D-23's measured rate ... divided by the worker count Task 3 fixes". Task 4's corpus comparison measured that model wrong: the same 1,413,907,546-byte corpus took 49,089 ms through the four-worker pipeline and 53,007 ms through the sequential `pass::run` - four workers bought 8%, not 4x, because SQLite's single writer plus the derived rows and the FTS index dominate the parse and compression that were moved off it (which is D-11's own stated reason for a small fixed count). Dividing by `WORKERS` would print "about 10s" over a corpus that takes fifty. D-23 requires a measured rate rather than a guess, so the estimate is calibrated on the pipeline's own measurement, and a unit test asserts it is NOT the single-threaded-over-workers figure. The printed line still says it is an estimate from a measured rate rather than a promise.
- [deviation] Task 3 `Action:` says to reuse `pass.rs`'s `runs`-row writing. `pass::record_pass` is a private `fn` and `crates/verbatim-core/src/ingest/pass.rs` is not in this plan's `files:` lease, so it cannot be called from `ingest/backfill.rs` and cannot be made callable without staging an undeclared path, which `lease-check` refuses. `Summary`, `PassOutcome` and `note` are public and are reused unchanged; the `runs` INSERT is a second copy, field for field, carrying a comment that says so. The per-file failure / divergence-flag arm of `pass::walk` is duplicated for the same reason. See open items.
- [deviation] Task 5 as written ("start the detached backfill" unconditionally) broke `crates/verbatim/tests/doctor.rs::a_data_directory_that_does_not_exist_is_a_state_and_stays_absent`, which installs into a fixture whose transcript tree is empty and then requires AC6's "doctor against a data directory that does not exist creates nothing" - the backfill was creating the store between install and doctor. Fixed at the cause rather than in the test (which is outside this lease): `backfill::start` returns `false` without spawning when the estimate found no transcripts at all, because a tree with nothing in it is archived by doing nothing, and install then says the hooks take it from the next session. Both AC6's test and Task 5's Verify pass.
