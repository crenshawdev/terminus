Deviations:

[deviation] Task 5's `Verify:` and the plan's `## Must be true when done` cannot both hold as written. The Must-be-true line says "without `--yes` and without a TTY it refuses rather than assuming", which is an `IsTerminal` gate; the `Verify:` also requires "a run whose confirmation is answered `n` exits 0 and leaves all three untouched", which no test can produce under that gate without a pty, and `std` has none. Implemented so that install asks, reads the answer, and refuses **when there is no answer to read** (EOF, closed, or unreadable stdin) naming `--yes`. That satisfies every clause of the `Verify:` and still prevents the failure the rule names - a scripted install that silently took defaults it never showed anyone - because an answer that arrives on a pipe was given, not assumed. `IsTerminal` is retained and decides only whether the question is printed as an inline prompt or on its own line.

[deviation] The plan's six tasks are not separately commitable in this codebase. Tasks 1, 3, 4, 5 and 6 all land in `crates/verbatim/src/cmd/install/mod.rs`, and each of their `Verify:` clauses runs the whole `verbatim install` command, so no per-task subset is testable. More decisively, the project's lint gate is `cargo clippy --all-targets -- -D warnings`: a commit holding only Task 2's `json_file.rs` was built and produced 23 dead-code **errors**, because a module with no live caller fails that gate. Committed instead as the split this repo already uses for phase 4 plan 1 - one `feat` commit for the implementation and one `test` commit for the integration tests - with both states independently built, linted and tested before committing. Every task's `Verify:` was observed.

[deviation] Task 6's Action has install "offer to raise" `cleanupPeriodDays` after writing. As first built, that second question could return a failure, and an install that had already written the binary and both settings files exited 1 - reporting that nothing worked when everything had. The offer now takes its default (no change) when there is no answer to read, and only the pre-write confirmation can refuse. Caught by `an_accepted_confirmation_writes_all_three_after_showing_the_diff`, which is the test that supplies exactly one answer.

Open items:

- `cargo fmt` reformats two pre-existing statements in `crates/verbatim/tests/hook.rs` (PLAN-1's file, outside this plan's lease). Reverted rather than committed. `cargo fmt --check` is therefore not clean on the tree; the project's detected lint command, `cargo clippy --all-targets -- -D warnings`, is. Worth one `cargo fmt` commit against PLAN-1's file by whoever owns it.
- Declined a general-purpose JSON value API on `json_file::Json`. There is no `remove`, no `as_bool`, no iteration over arrays beyond `items()`, and `keys()` is `#[cfg(test)]`: the two edits this plan makes are "append a member" and "append an array element", and PLAN-3's `uninstall` and `doctor` will state what they need. `Member`'s fields stay private for the same reason.
- Declined a minimal multi-hunk diff. `json_file::diff` trims the common prefix and suffix and aligns the single remaining block by LCS, so a change at two distant points in one file would print one hunk spanning both. Install's own edits are clustered - the four hook entries all sit inside `.hooks`, the server inside `.mcpServers` - so the rendered output is already the change and not the file; a hunk splitter becomes worth it when a task edits two distant keys.
- `verbatim install` writes hooks into the **first** configured root's settings file only. The summary names every root and says so when there is more than one, but a multi-root user gets hooks in one place by design. No requirement in this phase asks for more.
- The `align` LCS is quadratic and bounded by `ALIGN_LIMIT` (512 lines per side) after the prefix/suffix trim, falling back to removed-then-added above it. Nothing install does approaches the limit; it exists only to bound a file that changed under us between the read and the diff.
- F1 declined the byte-preserving splice. Install still cannot make a small edit to a file it did not format: the user's choice is to accept a re-rendered file or decline. A splice needs source spans on every parsed value and a merge of two edit sets; the finding admitted either resolution and the diff is the one that costs nothing at read time.
