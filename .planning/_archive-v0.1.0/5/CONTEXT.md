# Phase 5: Context Injection - Context

Gathered: 2026-08-20
Feeds: /cad-plan 5

## Scope boundary

In: The SessionStart resume brief and the UserPromptSubmit relevance injection, both emitted as `hookSpecificOutput.additionalContext` from the existing hook subcommands; the structural-threshold retrieval path and the `Hit` refactor that exposes match kind and entity count; per-session injection state as a file in the data directory; the dropped-turn complement derived from `compact_boundary` metadata; and the fail-open deadline that makes a missing, locked or corrupt store emit nothing and exit 0.
Out: Decision logging, outcome labels, replay and `verbatim stats` - all of FEED-01..FEED-04, phase 6. The per-session state file records only what INJ-04 needs to suppress within a session; it is not the durable decision record. Observations and the `observations` table - phase 7; the brief renders correctly with it absent. Retention, eviction and capture mode - phase 8. Any auto-tuner for the thresholds (PROJECT.md gates it behind evidence it converges). `SessionEnd` and `PostCompact` stdout: neither event has an `additionalContext` variant and both keep writing nothing.
Deferred: None - the size check kept all seven criteria in this phase.
Plan shape: multiple plans, same phase

## Durable decisions

- D-01 (Hook stdout surface): Injection output is one JSON object on stdout carrying `hookSpecificOutput.hookEventName` equal to the event that fired and the text in `hookSpecificOutput.additionalContext`; only `SessionStart` and `UserPromptSubmit` have such a variant. Evidence: verified 2026-08-20 against the installed bundle `/home/john/.local/share/claude/versions/2.1.237` (offset 309583000, the `hookSpecificOutput` discriminated union) - `SessionStart` accepts `{additionalContext, initialUserMessage, sessionTitle, watchPaths, reloadSkills}`, `UserPromptSubmit` accepts `{additionalContext, sessionTitle, suppressOriginalPrompt}`, and neither `SessionEnd` nor `PostCompact` appears in the union; the dispatcher at offset 312932800 throws `Hook returned incorrect event name` on mismatch and at 312965800 a stdout starting with `{` that fails schema validation becomes a `hook_non_blocking_error` shown to the user; `crates/verbatim/src/cmd/hook.rs` module doc; phase 4 D-15. If wrong: a brief emitted under the wrong `hookEventName`, or as bare JSON, is a red non-blocking-error banner on every session start rather than silence, and INJ-06's "any failure emits nothing" is violated by the success path.
- D-02 (Hook stdout surface): Everything injection needs arrives through the stdin payload, `verbatim.toml` and the store - the hook argv stays exactly `["hook", "<event>"]` and gains no flag. Evidence: `crates/verbatim/src/cmd/install/targets.rs:152` (`hook_args` is literally `["hook", event]`), the module doc at `:46-55` on never rewriting a written entry, phase 4 D-01, and `crates/verbatim/src/cmd/hook.rs::parse` rejecting anything but one positional event. If wrong: injection needs a new argument, which means rewriting every user's `settings.json` hook entries on upgrade - the exact version-skew class INST-03 and phase 4 AC5 were built to eliminate.
- D-03 (Deadline): INJ-06's deadline is enforced two ways at once - a short busy timeout on an injection-specific read-only open, plus a watchdog thread that abandons the work and exits 0 at the deadline. Evidence: `crates/verbatim-core/src/store/open.rs:46` `const BUSY_TIMEOUT_MS: u32 = 5_000;` applied on the read-only connection at `:199`; `crates/verbatim-core/src/ingest/lock.rs:1-10` states a writer blocking on the busy handler "would blow the 50 ms budget"; backfill measured holding the store 49 s over the real corpus (`.planning/phases/4/SUMMARY.md`); `crates/verbatim/src/cmd/hook.rs::DRAIN_DEADLINE` is the existing unjoined-thread pattern; `.planning/PROJECT.md:74`. The two cover different failures: the busy timeout turns lock contention into an immediate `SQLITE_BUSY` that phase 3 D-10's "empty result with a reason" path already handles gracefully, and the watchdog catches what a busy timeout cannot see - a slow query or a large blob. If wrong: a prompt submitted during a backfill blocks the user for five seconds, on exactly the machine state that provoked it.
- D-04 (Retrieval): The structural threshold cannot be read off a `Hit` as it stands - injection needs `Hit` to expose the `EntityMatch::Exact` versus `Covered` kind and the number of distinct matched entities, both of which `weight_by_entities` currently collapses into the scalar `Hit::entity_score`. Evidence: `crates/verbatim-core/src/recall/search.rs` - `Hit` carries only `entity_score: f64`, and `weight_by_entities` sums `idf * weight` per `(kind, value)` into `by_turn`, discarding kind and count; `crates/verbatim-core/src/recall/query.rs::EntityMatch` already distinguishes the two; the `TAIL` doc comment anticipates it ("phase 5 reads rank 1..3 and a nondeterministic tie would make its threshold fire on a different turn each time"). If wrong: INJ-03's two conditions get approximated by a score cutoff, which `DESIGN-BRIEF.md:245` forbids outright ("BM25 scores aren't comparable across queries"), and the free-text-only case becomes indistinguishable from a weak entity hit.
- D-05 (Retrieval): A prompt naming a file path only produces an `Exact` entity match after the path is resolved against the payload's `cwd`, because stored path entities are overwhelmingly absolute while a user types a relative one. Evidence: measured 2026-08-20 over 120 randomly sampled real transcripts (18,558 records) under `/home/john/.claude/projects`, parsing each `tool_use.input` for `file_path`/`path`/`notebook_path` - 1,029 absolute versus 2 relative (Read 669, Edit 286, Write 76); `crates/verbatim-core/src/index/entity.rs::normalize_path` only trims quotes and a `:line:col` suffix, never absolutizing; `crates/verbatim-core/src/recall/query.rs::matches_entity` requires every token of the stored value to be present in the query, so `/code/verbatim/crates/x.rs` cannot match a query of `crates/x.rs`. If wrong: AC3's headline case never fires for any prompt that does not spell the full absolute path, and the phase ships as permanent silence that every test written against an absolute-path fixture still passes.
- D-06 (Injection state): INJ-04's per-session suppression state lives in a per-session file in the data directory, keyed on `session_id`, outside SQLite entirely. Evidence: `crates/verbatim-core/src/store/schema.rs::TABLES` lists ten tables and none is a decision or injection log; `DESIGN-BRIEF.md:65` reserves `decisions`/`labels` for phase 6; `crates/verbatim/src/cmd/read.rs` opens `Store::open_read_only` on every read path (phase 3 D-10) while `Store::open` would `create_dir_all`, `initialize`, `bring_forward` and set two pragmas (`crates/verbatim-core/src/store/open.rs:101-142`). The trade-off settled against a SQLite table: a write on the prompt path is the one thing INJ-06 cannot tolerate, since a backfill holds the store for a measured 49 s and a blocked writer is strictly worse than a blocked reader; and suppression state is per-session and disposable, a different lifetime from phase 6's durable decisions log. If wrong: repeating an entity-bearing prompt injects the same turn on every prompt of a session - the "three near-misses are worse than silence" failure the phase exists to prevent.
- D-07 (Compaction): The dropped-turn set is the complement of `preservedMessages.uuids` over `turns.uuid` for the session, read from `compaction_boundaries.metadata`. It is NOT `allUuids`, NOT `preservedSegment`, and NOT "everything before `headUuid`". Evidence: measured 2026-08-20 across all 3,141 real `.jsonl` files - exactly one `compact_boundary`, at record index 49 of a 65-record file; of the 29 uuid-bearing records before it, 23 are dropped under both `preservedMessages.uuids` and `allUuids` (identical answers); preserved records sit at indices 31-35 and 41, and record 43 precedes the boundary and is not preserved, so the preserved set is not a suffix; `preservedSegment.anchorUuid` resolves to record index 50, AFTER the boundary; two of the eight `allUuids` are absent from the file entirely; every dropped record is a `TURN_TYPES` type and the 20 non-turn records before the boundary carry no uuid. Schema support: `turns.uuid` with `idx_turns_uuid`, `UNIQUE (session_key, turn_seq)`, `compaction_boundaries(turn_id -> turns.id)` (`crates/verbatim-core/src/store/schema.rs`), `store::split_turn_id`; phase 2 D-08 and `crates/verbatim-core/src/derive.rs:143-157` left this to be derived here. If wrong: `preservedSegment` yields a dropped set including a turn still in context, and "everything before `headUuid`" silently loses record 43's class of turn - exactly the "things this session knew ten minutes ago" the requirement targets.
- D-08 (Compaction): "The first prompt after a compaction" is triggered by a `SessionStart` whose `source` is `"compact"` writing an injection-owed flag into the D-06 state file; the next `UserPromptSubmit` consumes it, derives the dropped set, injects and clears it, and the flag persists until it fires rather than being lost. Evidence: the source enum `"startup","resume","clear","compact","fork"` is present in bundle 2.1.237 and `SessionStart`'s hook matcher key is `n.source` (both verified by grep on 2026-08-20); phase 4 D-02 (`PostCompact`, because the boundary is appended after compaction); phase 4 D-18 measured a steady-state tree pass at 92 ms over 2,244 files; compaction is append-only into the same transcript so the boundary's `session_key` is the current session (`crates/verbatim-core/src/ingest/mod.rs:88-91, 155`, phase 2 D-01). The persisting flag is what kills the race against the boundary row being committed: if the row is not there yet, the debt carries to the following prompt instead of being silently dropped. If wrong: AC5 is unreachable on a contended machine and non-deterministically green in tests. Note: the `source` enum is verified but the emit site proving compaction fires `SessionStart` was not located in the bundle - the first plan verifies this against a live compaction before building on it, falling back to reading the store's boundary row at `UserPromptSubmit` (accepting the race) if it does not hold.
- D-09 (Resume brief): The index pointer's counts are read through the project-only projection plus a targeted count, never through `config::visible::sessions`. Evidence: `crates/verbatim-core/src/config.rs`, `visible::projects` doc - measured on a store shaped like the real one (2,000 sessions, 250,000 turns, warm) `sessions()` costs 6.2-6.8 ms against 0.56-0.58 ms for the project-only join, and the comment says outright "The whole phase 5 budget is single-digit milliseconds"; `visible::counts` is built on `sessions()` and inherits the cost. If wrong: the brief spends the whole budget on a per-session `count(*)` over `turns` before reading a single turn, and AC1 fails on any real store while passing on every fixture.
- D-10 (Resume brief): INJ-01's "working-state delta" is branch-only, sourced from the archive - the branch the last session ended on, from `session_meta.branch`. No git subprocess runs on the SessionStart path. Evidence: `crates/verbatim-core/src/store/schema.rs` `session_meta` has `branch TEXT` and nothing else git-shaped - no commit sha, no dirty-file list, no HEAD column; `crates/verbatim-core/src/project.rs` is the only `std::process::Command` user in core and runs `git rev-parse --show-toplevel` behind a `GIT_BUDGET`; phase 3 D-12 bars it from the cold-start path ("process spawn is the 10-30 ms the cold-start budget is made of"). This knowingly under-delivers `DESIGN-BRIEF.md:230` ("git HEAD then vs now, branch, dirty files"): both alternatives buy a fuller delta with a git call at SessionStart, and 10-30 ms against a single-digit-ms budget is not a trade this phase can make. The model can check live git itself in one cheap tool call. If wrong: the brief either blows AC1's wall budget or ships a block that does not deliver what INJ-01 names.

## Decisions

- D-11 (Hook stdout surface): The three existing `assert!(output.stdout.is_empty())` sites in `crates/verbatim/tests/hook.rs` stay true after phase 5 without editing them, because each runs against a temp data dir whose only project key can never be the fixture payload's `cwd`. The phase-4 contract that actually changes is the 10 ms p99 budget, which now absorbs a read-only store open plus the injection queries. Evidence: `crates/verbatim/tests/hook.rs:343` (`BUDGET: f64 = 10.0`, `RUNS: usize = 100`), `:538`; the fixtures `tests/fixtures/hooks/*.json` all carry `"cwd":"/data/code/verbatim"`; measured phase-4 headroom is large - debug-build p99 of 0.76 / 0.65 / 0.69 / 0.68 ms per event (`.planning/phases/4/SUMMARY.md`). If wrong: three phase-4 tests fail as soon as injection lands and the budget test must be rewritten in the same commit that adds the feature, hiding whether the regression is timing or output.
- D-12 (Retrieval): The scope for both injection paths is resolved from the payload's `cwd` field, not from `std::env::current_dir()`. Evidence: `crates/verbatim-core/src/recall/scope.rs::Scope::Directory` is documented as taking the directory "as a value rather than something this module reads for itself", precisely so two front ends do not re-resolve it; `crates/verbatim/src/cmd/read.rs::scope` uses `Scope::current_directory()` for terminal commands only; the hook payload's `cwd` is a base field (phase 4 D-14). If wrong: a hook spawned with a working directory Claude Code chose (a plugin root, a worktree, `/`) scopes to the wrong project or to `Reason::UnknownProject`, and injection is silent in exactly the sessions with the most history.
- D-13 (Retrieval): Injection bounds how many distinct sessions it excerpts, or bypasses `search::run`'s excerpt step until the threshold has already fired. Evidence: `crates/verbatim-core/src/recall/excerpt.rs` module doc ("One blob per session per search (D-20) ... reading one turn materializes the whole compressed session - up to 10.1 MB uncompressed"); `search::run` calls `excerpt::attach` unconditionally after truncation; measured 2026-08-20 over all 3,141 real `.jsonl` files (1.42 GB) - p50 273 KB, p90 1.03 MB, p99 2.6 MB, max 10.1 MB uncompressed. If wrong: a prompt whose three candidates land in three large sessions spends milliseconds in zstd on the prompt path, and the budget failure appears only for users with big sessions, never in a fixture-sized test.
- D-14 (Injection state): A new table declared in `CREATE_SQL` does not reach an already-initialized store - only a `DERIVED_SCHEMA` bump (which forces a reindex) or an explicit on-demand create would put it there. This is the constraint that makes D-06 a file rather than a table. Evidence: `crates/verbatim-core/src/store/open.rs:101-142` - `initialize()` runs `CREATE_SQL` only when `inspect` returns `StoreState::Fresh`, and an existing store gets `bring_forward` (columns only); `crates/verbatim-core/src/reindex.rs:68` is the only other `execute_batch(schema::CREATE_SQL)`; the schema file documents the same mechanism for `idx_session_meta_project` (`schema.rs:104-112`, phase 3 D-19). If wrong: injection state fails with `no such table` on every existing user's store while every fresh-store test passes, or the phase forces a full ~49 s rebuild on the first hook-spawned pass after upgrade.
- D-15 (Injection state): INJ-04's "already visible in the session" is answered from the archive's own turns for the current session (`turns.session_key` = the canonicalized `transcript_path` from the payload), not by reading the live transcript at prompt time. Evidence: `session_key` is the canonicalized transcript path (`crates/verbatim-core/src/ingest/mod.rs:59-60, 88-91`) and `idx_session_meta_path` indexes it; all four hooks spawn an ingest so the session is archived incrementally by byte watermark (phase 4 D-18); a live read costs the measured p90 of 1.03 MB and p99 of 2.6 MB per prompt. Accepts a small duplication window at the head of a session. If wrong: a turn the user is currently looking at gets re-injected, which reads to the user as the system repeating itself.
- D-16 (Resume brief): The token budget in INJ-01/INJ-03 is enforced against a byte or character proxy, not a real tokenizer. Evidence: `Cargo.toml` lists eight workspace dependencies, each with a comment justifying its cost against a measured 0.408 ms startup floor (phase 4 D-04/D-11), and there is no tokenizer; `crates/verbatim-core/src/lib.rs` claims the crate "links no async runtime, no HTTP client and no thread pool"; existing budgets are already byte-shaped (`EXCERPT_CHARS = 240`, `MAX_BODY_BYTES`, `MAX_EXPANSION_BYTES`). Independent ceiling: bundle 2.1.237 persists any hook stdout over 10,000 characters to disk and replaces it with a reference (offset 312932800). If wrong: the configured budget is enforced against a proxy that miscounts code-heavy excerpts by a factor a user notices, or a tokenizer crate lands on the cold-start path the whole architecture is shaped around.
- D-17 (Resume brief): "The last session in this project" is ordered by `session_meta.last_turn_at`, rendered truncated to `YYYY-MM-DD`; `is_final` cannot be used because it is declared and never written. Evidence: `crates/verbatim-core/src/store/schema.rs:79` declares `is_final INTEGER` and a grep across `crates/verbatim-core/src` finds no writer (the only non-schema hit is a comment at `ingest/mod.rs:958`); `first_turn_at`/`last_turn_at` are written at `ingest/mod.rs:967-968`; the stored format is the fixed `NNNN-NN-NNTNN:NN:NN.NNNZ` shape phase 3 D-23 measured over 22,412 turns; INJ-02's rounding rule matches `DESIGN-BRIEF.md:239`; phase 3 D-22 warns intra-session timestamps run backwards in 31 of 62 sampled transcripts. If wrong: "where you left off" names a session that is not the most recent, and because the ordering is over stored values the wrong answer is stably wrong - INJ-02's byte-identity criterion passes while the content misleads.
- D-18 (Config): Injection settings are new keys in `verbatim.toml`, and the brief must render correctly with the `observations` table absent, since phase 7 owns it. Evidence: `crates/verbatim-core/src/config.rs::FileConfig` carries only `roots` and `exclude`, with the documented rule "Unknown keys are ignored rather than rejected: this file will grow across phases"; a grep for `observations` across `crates/` returns nothing outside `DESIGN-BRIEF.md:65` and the phase-7 roadmap entry. If wrong: either the token budget is a hardcoded constant when INJ-01 says "configured", or the brief queries a table that will not exist until phase 7 and every SessionStart emits nothing.

## Acceptance criteria

- [ ] AC1: SessionStart against a store with indexed history for the payload's project emits exactly one JSON object whose `hookSpecificOutput.hookEventName` is `SessionStart`, whose `additionalContext` is within the configured budget, at p99 under the asserted wall budget over 100 runs.
- [ ] AC2: Two SessionStart runs against an unchanged store produce byte-identical stdout, and no substring matching a time-of-day pattern appears anywhere in the output.
- [ ] AC3: A UserPromptSubmit prompt naming a path relative to the payload `cwd` that a past session edited (stored absolute) emits that turn; the same prompt with the path removed emits nothing and exits 0.
- [ ] AC4: The same entity-bearing prompt fed twice under one `session_id` injects on the first and emits nothing on the second, with the suppression reason readable in the per-session state file.
- [ ] AC5: After a SessionStart with `source: "compact"`, the next UserPromptSubmit draws candidates only from turns absent from `preservedMessages.uuids`, at most 3; a later prompt in the same session no longer does.
- [ ] AC6: With the store file deleted, and separately with the store held by an exclusive writer past the deadline, UserPromptSubmit exits 0 with empty stdout inside the deadline.
- [ ] AC7: A prompt whose only match is free text - no rank 1-3 exact entity, no two independent entities co-occurring - emits nothing.

## Flagged assumptions

- Volatile SessionStart `additionalContext` busts the Anthropic prefix cache, which is INJ-02's entire stated rationale (`DESIGN-BRIEF.md:239`) - Unclear; the bundle shows the text is delivered but nothing observable locally proves the cache consequence. If wrong: a correct requirement has a wrong justification; the byte-identity criterion stands on its own either way.
- Compaction actually fires a `SessionStart` carrying `source: "compact"` - Likely; the source enum is verified present in bundle 2.1.237 and `SessionStart`'s matcher key is `n.source`, but the emit site was not located. D-08 carries the verify-first step and the fallback.
