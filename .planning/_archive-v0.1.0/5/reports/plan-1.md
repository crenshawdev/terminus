Deviations:
- [deviation] Task 4's Action asserts that lowering the read-only connection's busy timeout makes a prompt submitted against a held store "get an immediate `SQLITE_BUSY`". Measured otherwise: `Store::open_read_only` applies its own 5 s timeout and runs a `sqlite_master` query BEFORE returning, so the lowered timeout arrives too late to bound the open. Against a store held under `PRAGMA locking_mode = EXCLUSIVE`, a holder in the SAME process makes the open wait the full 5,011 ms, while a holder in ANOTHER process (the real case, and AC6's) is reported back in about 6 ms. Both mechanisms were still built as the plan asks; the constant's doc and both tests now state what each one actually bounds - the busy timeout covers every statement after the open, and the hook's watchdog is the only general bound on the wait. AC6 is met either way and no criterion changed. Bounding the open itself would need `crates/verbatim-core/src/store/open.rs`, which is outside this plan's lease.
- [deviation] Task 5's Verify says the fixture is the captured bytes with three identity fields replaced. Two more were replaced. `prompt_id` is a UUID minted by the same real session as `session_id`, so it is the same class of artifact the "real transcripts never enter this public repository" rule names, and it now carries the synthetic UUID the other four fixtures use. `model` carried a build-specific name for the model the live session ran (not a published `claude-<name>-<date>` id), and this repository is public OSS; it now carries the same value `hooks/session-start.json` does. `hook_event_name` and `source` - the only two fields anything reads, and the two the task exists to establish - are exactly as captured. Both substitutions are stated in `tests/fixtures/README.md` beside the fixture.
- [deviation] The capture contradicts `tests/fixtures/README.md`'s account of the recorded payloads, which task 5 did not anticipate. The live `"compact"` line carries `prompt_id` and the live `"startup"` line does not, so `prompt_id` is not the unconditional base field the README describes; and neither live line carried `permission_mode`, `agent_type` or `session_title` at all. Nothing in the codebase reads those four fields, so the four older fixtures were left untouched and the README and `Payload::source`'s doc comment now both record the contradiction and say to re-observe before reading one.
