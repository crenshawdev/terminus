# Phase 6: Feedback Loop - Context

Gathered: 2026-08-20
Feeds: /cad-plan 6

## Scope boundary

In: The per-prompt decision record written on the UserPromptSubmit path and drained into a `decisions` table by ingest; the `Hit` extension exposing matched `(kind, value_norm)` pairs; the `is_final` idle-rule writer and the SQL label join producing `hit` / `false positive` / `miss` / `wasted budget` in a `labels` table; `verbatim replay` as a shipped subcommand with threshold override flags; `verbatim stats` under the existing `--json` envelope; and the schema path that puts both new tables on already-initialized stores without a reindex.
Out: Any auto-tuner acting on the labels - PROJECT.md gates it behind evidence from this phase that it converges. Observations (phase 7). Retention, eviction, capture mode (phase 8); `is_evicted` stays unwritten. A `SessionEnd`-driven finalize path - finalization is the idle rule only (D-09). Promoting live-path thresholds into `verbatim.toml` (D-08 keeps them compile-time). MCP exposure of stats or replay (DESIGN-BRIEF bars non-recall tools).
Deferred: None - the size check kept all six criteria in this phase.
Plan shape: multiple plans, same phase

## Durable decisions

- D-01 (Decision record): The decision record is produced on the prompt path as a file under the data directory (the existing tmp+rename pattern from `inject/state.rs`, written on the abandoned hook thread) and drained into the `decisions` table by a later `verbatim ingest` pass - the hook itself never writes SQLite. Evidence: `crates/verbatim-core/src/inject/state.rs` (D-06/D-14 module header and writer), `crates/verbatim-core/src/inject/mod.rs:19-27` ("Nothing here writes to the store, creates one or locks one"), `crates/verbatim/src/cmd/hook.rs:98-108` (50 ms watchdog), phase 5 D-06. If wrong: a SQLite write on UserPromptSubmit sits behind the ingest/backfill writer (measured 49 s hold), the user's prompt blocks on exactly the machine state that provoked it, and the 10 ms p99 assertion in `crates/verbatim/tests/hook.rs:343-376` fails.
- D-02 (Schema): `decisions` and `labels` are added to `CREATE_SQL` and `schema::TABLES` and reach an already-initialized store through `bring_forward`'s missing-table arm on the next `Store::open` - no `DERIVED_SCHEMA` bump, no forced reindex. This CORRECTS phase 5 D-14, which the code contradicts: `bring_forward` computes `missing_tables` from `schema::TABLES` and runs `CREATE_SQL` when any is absent, unchanged since phase 2 (`a292f0c`). Evidence: `crates/verbatim-core/src/store/open.rs:326-359`, `crates/verbatim-core/src/store/schema.rs:107-115` (the index comment states the same mechanism), `crates/verbatim-core/src/recover.rs:89-95` (the ingest pass opens through `Store::open`). If wrong: every upgraded machine hits `no such table: decisions` on the first stats run, or the phase forces the measured ~50 s in-lock rebuild on the first hook-spawned pass after upgrade.
- D-03 (Schema): `decisions` stays out of `schema::DERIVED_TABLES` - `verbatim reindex` must never drop it, because a decision records prompt-time state no blob replay can reconstruct. This knowingly diverges from `DESIGN-BRIEF.md:92`, which lists decisions among the rebuildable set. Whether `labels` splits off as droppable (recomputable from `decisions` + blobs) is the planner's call. Evidence: `crates/verbatim-core/src/reindex.rs:52-70` (drops every `DERIVED_TABLES` entry), `crates/verbatim-core/src/store/schema.rs:228-240`. If wrong: the first reindex or `DERIVED_SCHEMA` bump silently deletes the entire logged history FEED-03's diff and FEED-04's precision are computed over, with no integer in `meta` saying it happened.
- D-04 (Decision record): A decision anchors to its session by `session_id` plus a wall-clock timestamp, never by `turn_seq` - the injector deliberately never reads the live transcript (`inject/prompt.rs:393-414`) so it cannot know a turn index; ingest resolves the anchor to a turn at label time. This diverges from `DESIGN-BRIEF.md:275`, which puts `turn_seq` in the record shape. Evidence: `crates/verbatim-core/src/inject/prompt.rs:393-414`, `crates/verbatim-core/src/inject/mod.rs:56-67` (payload carries no turn index). If wrong: FEED-02's "referenced downstream" join has no upstream boundary - the labeler cannot tell turns before the injection from turns after it, and every decision in a busy session labels `hit`.
- D-05 (Retrieval surface): `Hit` gains the matched `(kind, value_norm)` pairs so `candidates[].matched_on` can be recorded; today `Matched.values` holds exactly those pairs and only `values.len()` survives into `Hit::entity_count`. This also touches the `search --json` contract (`docs/json-shapes.md:71-78`). Evidence: `crates/verbatim-core/src/recall/search.rs:401-411, 518-525`, `crates/verbatim-core/src/index/entity.rs:27-38`. If wrong: the logged candidate can say only "matched 2 entities", so a replay diff cannot attribute a label change to a path rule versus a symbol rule - the one question FEED-03 exists to answer.
- D-06 (Labeling): "Finalized" is written by an idle rule at ingest: a pass marks `session_meta.is_final` when `last_turn_at` is older than a threshold (~6 h; measured 2026-08-20 over 150 sampled transcripts, 1 internal idle gap over 1 h, 0 over 6 h). No `SessionEnd`-driven finalize path: `SessionEnd` does not fire on crash (`DESIGN-BRIEF.md:116`) and phase 4 D-18/phase 5 D-02 fix the hook argv so the spawned pass cannot know which session ended - the idle rule is one mechanism that covers both. `is_final` is declared and currently written by nothing (`schema.rs:79`, `ingest/mod.rs:955-958`). If wrong: nothing is ever labeled, or live sessions are labeled mid-flight and every decision whose downstream turns are not yet ingested becomes a permanent `false positive`.
- D-07 (Labeling): The label join runs entirely in SQL over `entities` - the injected turn's `(kind, value_norm)` rows against rows of later turns in the same session - never by re-reading transcript text or blobs. Base rate measured 2026-08-20 (150 transcripts, 4,618 path mentions in 344 path-naming prompts): 41.1% of a prompt's path mentions recur later in-session, so the proxy separates hit from false positive. Evidence: `crates/verbatim-core/src/store/schema.rs:160-175` (indexed `(turn_id, kind, value_norm)`), `crates/verbatim-core/src/ingest/pass.rs:144-212`, `DESIGN-BRIEF.md:285-290`. If wrong: labeling decompresses session blobs inside the ingest lock (p90 1.03 MB, max 10.1 MB per session) and the 92 ms steady-state pass becomes a per-session decompression sweep.
- D-08 (Thresholds): Live-path injection thresholds stay compile-time constants (`RANKED`, `COMPACTED_RANKED`, `ENTITY_RANK`, `CO_OCCURRING`, `MAX_TURNS`, `MAX_CANDIDATES` in `inject/prompt.rs:62-99`); `verbatim replay` accepts CLI override flags so one build sweeps variants; every decision record logs the values in force. The precision-first defaults stay non-detunable by config, per `DESIGN-BRIEF.md:245`. If wrong: AC4 becomes a rebuild-and-compare loop testing one variant per build, and the deferred auto-tuner has no recorded baseline to converge against.
- D-09 (Replay): `verbatim replay` is a shipped subcommand of the binary, under the existing `--json` envelope and a `docs/json-shapes.md` section, runnable against a real user's logged history - not a testkit-only or hidden verb. User-settled 2026-08-20. If wrong: AC3's diff exists only inside `cargo test` and the product's "retrieval measurable against history" pitch has no user-reachable surface.
- D-10 (Replay): "The index as it stood" is reconstructed by bounding replay's candidate set with a monotone watermark recorded in each decision row (max `sessions.session_no` at decision time, or the current `runs.id`), never by snapshotting the database. `session_no` is assigned in ingest order and stable across rebuilds (`schema.rs:21-46`); `turns.ts` is transcript time, not ingest time, and cannot answer "was this row indexed yet". Evidence: `crates/verbatim-core/src/store/schema.rs:21-46`, `crates/verbatim-core/src/ingest/mod.rs:871`. If wrong: replay scores historic prompts against turns archived after them, and FEED-03 certifies changes on hindsight.

## Decisions

- D-11 (Decision record): Every UserPromptSubmit writes a record, including prompts that return before the store opens because no candidate spelling was found (`inject/prompt.rs:207-217` early return). Roadmap AC "every prompt produces a decision record" and `DESIGN-BRIEF.md:272` ("non-fires are where miss data lives") settle it. Measured growth is bounded: median 2 user prompts per session, p90 10, max 50 over 150 sampled transcripts. If wrong: precision is computed only over prompts that reached the index and the miss/silence denominators are unmeasurable. [corrected by plan-1 deviation: a prompt on a machine with no data directory writes no record, because `Decision::save` will not create the directory - phase 5's INJ-06 test asserts a hook leaves nothing behind before the first ingest]
- D-12 (Decision record): "Tokens spent" and "tokens injected versus referenced" use the existing character proxy (`inject/mod.rs:182-208` `chars`/`clip`), no tokenizer crate, per phase 5 D-16. Evidence: `crates/verbatim-core/src/config.rs:121-131`. If wrong: a tokenizer lands on the cold-start path the architecture is shaped around.
- D-13 (Labeling): `miss` is defined against `recall_search`/`recall_get` tool calls appearing in the transcript, and reads zero on real history today - zero such `tool_use` blocks across all 3,217 transcripts measured 2026-08-20. Fixtures for AC3/AC5 must synthesize the calls. Evidence: `crates/verbatim/src/cmd/mcp/tools.rs:42-46`, `DESIGN-BRIEF.md:289`. If wrong: stats reports a miss count that structurally cannot move and the criterion asserts on a constant.
- D-14 (Stats): `verbatim stats` is a CLI-only data command under the existing envelope - `--json`, `{command, ok, reason, data}`, exit 0/1/2, a `docs/json-shapes.md` section, one `DATA_COMMANDS` row (`crates/verbatim/tests/cli.rs:621-631`). Never an MCP tool (`DESIGN-BRIEF.md:187`). Evidence: `crates/verbatim/src/cmd/json.rs:1-60`, `crates/verbatim/src/cmd/status.rs` as the nearest shape.
- D-15 (Replay): Replay opens the store with `Store::open_read_only` - no `create_dir_all`, no `initialize`, no `bring_forward`, no pragma - so "without touching the live store" is enforced by connection flags, not discipline. Evidence: `crates/verbatim-core/src/store/open.rs:144-223`, `crates/verbatim/src/cmd/read.rs:1-20`, phase 3 D-10.

## Acceptance criteria

- [ ] AC1: Three prompts fed to UserPromptSubmit - one that injects, one that fires nothing on threshold, one whose candidates are empty before the store opens - each yield a decision row after the next ingest pass, carrying entities, candidates with matched `(kind, value_norm)` pairs, suppressions with reasons, threshold values and char counts; the phase-4 hook p99 budget test still passes.
- [ ] AC2: On a fixture session past the idle threshold with one injected turn referenced downstream and one never referenced, an ingest pass sets `is_final` and labels them `hit` and `false positive` respectively; a session younger than the threshold gets `is_final` unset and zero labels.
- [ ] AC3: A fixture transcript containing a `recall_search` tool call for an entity a logged decision declined to inject gets that decision labeled `miss`.
- [ ] AC4: `verbatim replay` with a threshold override flag exits 0, reports a per-label diff across the logged history, and leaves the store file byte-identical.
- [ ] AC5: `verbatim stats` and `verbatim stats --json` report precision, miss count and chars injected versus referenced, validating against the documented shape; on a fixture with a known outcome mix the numbers equal the hand-computed values.
- [ ] AC6: `verbatim reindex` on a store holding logged decisions returns the same `decisions` rows after the rebuild; a store initialized by the phase-5 binary opened by this one gains `decisions`/`labels` with no reindex triggered.

## Flagged assumptions

- The 41.1% downstream-recurrence base rate makes "referenced downstream" a usable hit/false-positive separator - Likely; `DESIGN-BRIEF.md:298` itself calls it a weak proxy. If wrong: labels are noisy and the auto-tuner gate (evidence of convergence) correctly stays shut.
- Draining decision files into SQLite at ingest keeps the per-prompt filesystem write cheap enough that the universal write (D-11) stays inside the hook budget - Likely; the state-file writer already runs on the abandoned thread. If wrong: the p99 budget test catches it in AC1.
- Whether `labels` is derived-and-droppable or archival alongside `decisions` is the planner's call (D-03 fixes only that `decisions` survives reindex).
- The idle threshold value (~6 h) is calibrated on 150 sampled sessions with 0 misclassifications - Likely; a long-running session idle over the threshold mid-conversation would be finalized early and its later turns labeled against a closed decision set. If wrong: the threshold is one constant to raise.
