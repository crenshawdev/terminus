Deviations:
- [deviation] Task 1's Verify asserts a read-only open "leaves `verbatim.db` and its sidecars byte-identical". Measured: `verbatim.db` is byte-identical and no pre-existing file changes, but SQLite itself materializes `verbatim.db-shm` (32 KB) and an empty `verbatim.db-wal` for any WAL database opened read-only in a writable directory - the shared-memory index is how a WAL reader finds a snapshot at all. The only way to suppress it is the `immutable=1` URI parameter, which tells SQLite the file cannot change and is false here (ingest writes concurrently under WAL), so it would trade a created index file for wrong query results. The plan already anticipates the other side of this mechanism: task 1's own text asks for "a WAL database on a medium where the shared-memory index cannot be created" to be reportable, which is `Error::StoreUnreadable`. Asserted the meaning instead: `verbatim.db` byte-identical, every pre-existing file byte-identical, the only additions those two, and the WAL empty because nothing was committed through it.
