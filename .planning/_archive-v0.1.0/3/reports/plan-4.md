Deviations: [deviation] Task 5's `Verify:` says a tool called with "an over-large limit" returns "a successful response whose content carries an empty result and a reason". The same task's `Action:` says the opposite two sentences earlier — "a caller's own limit may only lower it" — and `recall::search::Request::effective_limit` already clamps, documenting that "an over-large `limit` is a client being optimistic, not a caller error, and RCL-10 wants an answer rather than a refusal". Implemented as clamping: each of the three tools answers an over-large argument with a bounded, non-empty result carrying a reason naming the budget, asserted by `an_over_large_argument_is_lowered_to_the_budget_rather_than_refused`. The "reason" half of the criterion holds; the "empty result" half does not. Not escalated as a checkpoint because neither the plan's `## Must be true when done` nor CONTEXT AC6 asks for the empty-result arm — both scope the empty-result-with-reason contract to a *malformed* request, which is implemented and tested as written.

Open items:
- A line read off stdin is materialized whole by `read_until` before it is parsed, so there is no cap on the size of one JSON-RPC message. The client is a local process Claude Code spawned, and a cap would need incremental reading to buy anything, so nothing here changes; worth naming before any non-Claude-Code client is supported.
- The skip arm of the socket probe is not exercised on this machine, where `ss` is at `/usr/bin/ss`. It is a two-line `match` arm that prints and skips, checked by the compiler and not by a run.
- The MCP tool result shape (`{hits|turns|records, reason}` in one text block) is not written into `docs/json-shapes.md`, which PLAN-3 pinned as the *CLI* wire contract. The two are deliberately different formats; if the MCP shape is to be a stable contract too, it needs its own pinned document.
